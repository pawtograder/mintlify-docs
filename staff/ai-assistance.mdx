# AI assistance for helping students

Pawtograder can hand your own AI assistant the context it needs to help you
diagnose a student's problem. The AI buttons in the staff UI build a structured
prompt and copy it to your clipboard. You paste that prompt into an assistant
connected to Pawtograder's Model Context Protocol (MCP) server, and the assistant
fetches the help request, submission, test output, and assignment spec for
itself.

<Warning>
Pawtograder never calls a model. Every AI button in the product does exactly one
thing: it puts text on your clipboard. Nothing is sent to Anthropic, OpenAI, or
any other provider by Pawtograder, and no AI-generated text ever appears inside
Pawtograder.
</Warning>

## What the copied prompt contains

For a help request or a discussion thread, the prompt is instructions plus
identifiers — the class ID, the resource ID, and the submission and assignment
IDs when they are known. It does **not** contain the student's question, code, or
test output. Those only reach your assistant if the assistant can call the MCP
server, which means an assistant with no MCP connection has almost nothing to
work with.

The prompt also tells the assistant how to answer: a diagnosis that cites
specific code and test output, two draft replies (one Socratic, one direct), and
a verification checklist. That is a request in the prompt, not a guarantee about
what you get back — read the result critically before sending anything to a
student.

For a failing test, a build error, or a common error pattern, the prompt embeds
the error output directly (truncated at 4,000 characters for a single
test or build failure) along with the same tool guidance.

## Setting up

You need to be an instructor or grader in at least one course. The API Tokens
dialog is hidden from students entirely, and the token endpoint rejects anyone
else with "MCP tokens are only available to instructors and graders".

<Steps>
<Step title="Install an MCP-capable assistant">
Claude Desktop is what the in-product instructions assume; download it from
[claude.ai/download](https://claude.ai/download). Any client that can connect to
a remote MCP server over HTTP with a bearer token works.
</Step>

<Step title="Create an API token">
Open the user menu (your avatar, top right) and click **API Tokens**. In
**Create New Token**:

1. Enter a **Token Name** — the placeholder suggests things like "Claude Desktop"
   or "VS Code".
2. Choose a **Token Type**. The three buttons are **MCP (AI Assistants)**,
   **CLI (Command Line)**, and **MCP + CLI**. Pick **MCP (AI Assistants)** or
   **MCP + CLI**; a CLI-only token is rejected by the MCP server.
3. Click **Create Token**.

The token appears once, under **Token Created - Copy Now!**. Copy it before you
dismiss the panel — it is never shown again. Every token starts with `mcp_`,
whichever type you chose, and is valid for **90 days**.
</Step>

<Step title="Configure your assistant">
Scroll to **How to Use** in the same dialog. Under **MCP Client Configuration
(Claude Desktop)** is the exact JSON block for your deployment, with the server
URL already filled in. Copy it from there rather than typing it out, then paste
your token in place of `mcp_YOUR_TOKEN_HERE`:

```json claude_desktop_config.json
{
  "mcpServers": {
    "pawtograder": {
      "url": "https://api.<your-pawtograder-host>/functions/v1/mcp-server",
      "headers": {
        "Authorization": "Bearer mcp_YOUR_TOKEN_HERE"
      }
    }
  }
}
```

Claude Desktop reads its configuration from
`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS and
`%APPDATA%\Claude\claude_desktop_config.json` on Windows.
</Step>

<Step title="Restart and verify">
Quit and reopen your assistant. `pawtograder` should appear in its list of MCP
servers, offering the tools listed below.
</Step>
</Steps>

<Warning>
The MCP server lives on your deployment's **API** host, not the host you use the
web app on — typically `api.` plus your Pawtograder hostname. A URL built from
the web address serves the app, not the edge function, and the connection will
fail. Always copy the URL out of the **API Tokens** dialog.
</Warning>

<Note>
If you click an **AI** button before you have a token, Pawtograder opens a dialog
titled **Set Up AI Help with Claude Desktop** instead of copying anything. Its
steps are older than the block described above: it tells you to install an
`mcp-proxy` package and configure a `command`/`args` server, and it calls the
token screen "Settings → API Tokens". Use the **API Tokens** dialog and its
`url`-based configuration instead.
</Note>

## Where the AI buttons are

| Surface | Control |
|---|---|
| [Help request chat, in office hours](/staff/office-hours/help-requests#ai-help) | Robot icon button, **Get AI help** (tooltip "Copy AI help context") |
| A discussion thread | The same robot icon button, in the thread actions |
| Submission results, next to a failing test | Robot icon button, "Copy AI prompt to analyze this test failure" |
| Submission results, on a build error | Robot icon button, "Copy AI prompt to analyze this build error" |
| **Test Insights → Common Errors**, on an expanded error group | Button **AI Analyze** (tooltip "Copy AI prompt for analyzing this error pattern") |

All of them are hidden from students. The **AI Analyze** button covers up to ten
of the affected submissions and states in the prompt how many students hit the
pattern, so the assistant can judge whether it is a student mistake or a problem
with the test or the spec.

<Note>
Only the help-request and discussion buttons check whether you have a token. The
submission-error and **AI Analyze** buttons copy the prompt regardless, so an
assistant with no MCP connection will fail to fetch anything after you paste.
</Note>

### Feedback

Right after a copy, a small panel asks **How was the AI assistance?** with thumbs
up, thumbs down, and an optional comment box. It appears before you have had a
chance to use the prompt, so it is really asking about the context Pawtograder
gave you. The rating is recorded against the course and the resource you copied
from.

## Available MCP tools

The server exposes 16 read-only tools. See
[MCP Server](/developers/mcp-server) for the implementation and how to add more.

**Context**

- `get_help_request` — the help request with its full conversation history
- `get_discussion_thread` — the thread with its replies
- `get_assignment` — title, description, handout URL, due date, and points

**Submissions**

- `get_submission` — submission metadata and summary
- `list_submission_files` — the file list, without contents
- `get_submission_files` — file contents, filtered by glob pattern
- `list_submission_tests` — every test result, with an option to list only failures
- `get_test_output` — full output for one test
- `get_submission_build_output` — compilation and build errors
- `get_submissions_for_student` — every submission a student has made for an assignment

**Repositories**

- `list_grader_files` / `get_grader_files` — the grader/solution repository
- `list_handout_files` / `get_handout_files` — the template/handout repository

**Search**

- `search_help_requests` — related help requests
- `search_discussion_threads` — related threads

<Warning>
The prompts reference a `search_submissions` tool that the server does not
implement. If your assistant reports that tool as unavailable, that is why —
everything else in the tool list is real.
</Warning>

<Note>
`get_assignment` returns the assignment's handout URL, but there is no field in
the assignment forms for setting it, so it is empty in practice unless an
administrator populates it directly. Point your assistant at the handout
yourself if it needs the written specification.
</Note>

## Privacy and access control

- **Staff only.** Token creation and every tool call require an instructor or
  grader role, checked on the server, and the API Tokens menu is hidden while you
  preview the course as a student.
- **Same visibility as the web app.** Tool handlers query the database as you,
  under the same row-level security policies the app uses. There is no
  service-role escalation in the tool handlers.
- **No account data.** The `users` table is never queried by a tool handler, and
  the `is_private_profile` flag is never returned.
- **Revocable.** Tokens are long-lived signed tokens; revocation is checked on
  every request, so a revoked token stops working immediately.
- **Auditable.** Each token records a last-used timestamp.

<Warning>
A token is a bearer credential that grants your staff-level read access to course
data for 90 days. Treat it like a password, and revoke it if it may have leaked.
</Warning>

## Managing your tokens

The **API Tokens** dialog lists your tokens under **Your Tokens** with columns
**Name**, **Type**, **Status**, **Created**, **Expires**, and **Last Used**.
Type reads **MCP**, **CLI**, or **MCP + CLI**; status reads **Active**,
**Expired**, or **Revoked**; a token you have never used shows **Never**.

To revoke one, click the trash icon on its row. Revoked and expired tokens keep
their row but lose the button.

<Note>
The same dialog also issues tokens for the Pawtograder command-line tool and
shows its install and login commands. See [CLI](/staff/cli) for what the CLI can
do.
</Note>

## Using it well

Good candidates for AI assistance:

- A bug that spans several layers and resists a quick read
- A failure pattern several students have hit at once
- Drafting a long, well-structured explanation you would otherwise write by hand

Poor candidates:

- Questions you can answer in one line
- Course policy, which the assistant does not know
- Accommodations or anything sensitive about an individual student

Before you send anything to a student, check the cited line numbers and test
output against the real submission, check the advice against the assignment
specification, and cut anything that hands over the solution.

## Troubleshooting

### `pawtograder` does not appear in my assistant

- Confirm the configuration file is valid JSON.
- Confirm the URL is the one from the **API Tokens** dialog — the API host, not
  the web address.
- Confirm the token has not expired; tokens last 90 days.
- Restart the assistant completely after editing its configuration.

### "Access denied" or "Invalid or expired API token"

- Confirm your token's **Type** is **MCP** or **MCP + CLI**. A **CLI** token has
  no MCP scopes and is rejected.
- Confirm the token is still **Active** in **Your Tokens**, not **Expired** or
  **Revoked**.
- Confirm you still have an instructor or grader role in the course you are
  asking about.

### The assistant cannot see any course data

- Check that the `Authorization` header value starts with `Bearer mcp_`.
- Check that you are asking about the right class ID; every tool call is scoped
  to one class, and you only reach classes where you are staff.
- Remember that the copied prompt carries no student content. If the assistant is
  guessing, its MCP connection is not working.

### Token creation fails

**Create Token** stays disabled until the **Token Name** box has something in it.
If it is enabled and creation still fails, confirm you hold an instructor or
grader role in at least one active course.
