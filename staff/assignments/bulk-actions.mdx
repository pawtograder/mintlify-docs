# Bulk Actions

Pawtograder exposes several bulk operations across an assignment's
submissions so instructors don't have to click through one submission
at a time. All of them live on either the **Submissions** table on the
assignment's **Dashboard** tab or the **Grading Assignments** page.

## Selecting rows

The submissions table supports row selection via the leftmost checkbox
column:

- Click an individual checkbox to toggle a row.
- Click **All in view** in the column header to select every row that
  matches the current filters.
- Click **None** to clear the selection.

The **Release** and **Unrelease** buttons show the count of selected
rows (e.g. "Release 12 selected submissions") and become active only
when at least one selectable row is checked. Row selection does not
drive any completion action; see **Finalize grading** below. Rows for students who
haven't submitted yet are not selectable. The selection clears
automatically after a successful action or when you change column
filters.

## Finalize grading

The **Finalize grading** button on the assignment's **Dashboard** tab
marks every eligible incomplete review complete in one step. It is
intentionally not scoped to your row selection: it always acts on every
eligible review in the assignment.

A review is **eligible** when:

- All required rubric checks have been applied.
- Every criterion's minimum and maximum check counts are satisfied.
- The submission is a student's active submission and that student has
  not dropped the course.
- The review is not already complete.

Clicking the button opens a popover reporting how many of the
incomplete submissions can be finalized, and how many have missing
required rubric checks. Those are skipped. Confirm with the checkmark
to apply.

<Note>
Completing a review does not release it to the student. Use **Release**
(below) separately when you're ready to make grades visible.
</Note>

Use the **Grading Complete** column filter on the submissions table to
focus on only complete or only incomplete reviews.

## Grading Progress dashboard

There is no second, finer-grained bulk-completion flow. The **Grading
Progress Dashboard** tab on the Grading Assignments page has no bulk
actions and no row selection.
It reports each TA's pending and completed counts, and its one action,
**Generate Reminder Email**, copies a reminder message to your
clipboard for you to send yourself. See
[Grading Status](/staff/assignments/grading-status).

## Bulk Release and Unrelease

Once rows are selected on the submissions table, the **Release** and
**Unrelease** buttons publish or retract the selected reviews. Released
reviews become visible to students; unreleased reviews are hidden again
and grading comments unlock for graders to edit.

<Warning>
Unreleasing a review hides it from the student but keeps it in their
gradebook history. Don't unrelease without a plan to re-release — the
student may have already seen the previous grade.
</Warning>

## Reassign Grading by Grader

Reassignment is grader-centric rather than submission-centric: you pick
the grader whose remaining work needs redistributing, not a set of
submissions. From the **Grading Assignments** page, follow the
**Reassign Grading by Grader** link, then:

1. Select the grader whose remaining work you want to reassign.
2. Choose the rubric.
3. Set how many of that grader's incomplete submissions to reassign.
4. Choose the target role (**Instructors**, **Graders**, or
   **Instructors and graders**), optionally filter those staff by tag,
   and optionally name specific assignees.
5. Choose a load-balancing strategy: **Balance based on new
   assignments** or **Balance based on all assignments**.
6. Set the review due date.
7. Click **Prepare Reassignments**, adjust the draft in the
   drag-and-drop preview, then click **Reassign**.

Each new grader inherits the same rubric parts the original grader was
assigned, and declared grading conflicts are still respected. See
[Assigning Grading Tasks](/staff/assignments/grading-assignments) for
editing a single review assignment and for the bulk-assign algorithm.

## Bulk Review Due Date Updates

The **Bulk edit grading due dates** and **Bulk edit self-review due
dates** buttons on the Grading Assignments page update many review
deadlines at once:

1. Choose a rubric (required).
2. Set the new due date and time.
3. Optionally check **Only rows not yet completed** to skip finished
   reviews.
4. Click **Apply to matching rows**.

The system reports how many rows were updated. Grading-rubric and
self-review due dates are managed separately to avoid accidental
cross-edits. For per-student due-date changes use the inline edit
control on the submissions table or the student's gradebook row.

## Group Mentor Column

When at least one group has an assigned mentor, a **Group mentor**
column appears on the submissions table. Filter by mentor (or **No
mentor**) using the column header dropdown to scope any of the bulk
actions above to a specific mentor's groups.
