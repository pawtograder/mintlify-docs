# Assignment Dashboard

The assignment dashboard provides a centralized view of all key metrics and information for an assignment. Use this dashboard to monitor student progress, track submissions, manage grading workflows, and analyze rubric application patterns.

## Accessing the Dashboard

Navigate to any assignment to view its dashboard — it is the default landing page for each assignment. The dashboard has two tabs:

- **Dashboard** — score statistics, rubric breakdown, and the submissions table
- **Grading assigned to me** — your personal grading queue

## Dashboard Components

### Grading status panel

At the top of the dashboard, a compact panel shows grading progress and provides bulk actions:

- **Graded / Released counts** — how many submissions have completed reviews and how many have been released to students
- **Finalize grading** — marks every eligible submission review complete (those with all required rubric checks applied). Shows an eligibility preview before confirming. Does not release grades.
- **Release all** — makes grades visible to all students for every submission in the assignment
- **Unrelease all** — hides grades from all students (reverses Release all)

### Score statistics

Track student performance with real-time statistics, filterable by class section or lab section:

- **Total score** — min, average, max, and count across graded submissions, with a sparkline histogram
- **Autograder score** — same breakdown for autograder-only scores
- **Submissions per student** — distribution of how many attempts students have made

Expand **Show detailed distributions** to see full histograms for each metric.

### Rubric breakdown

Collapsed by default (to avoid unnecessary RPC calls), the rubric breakdown shows how often each rubric check was applied across a cohort of submissions.

**Visualizations:**
- **Bars** (default) — horizontal application-rate bars grouped by criterion
- **Options** — per-option breakdown for choice-style checks
- **Table** — sortable table of check name, applied count, and percentage
- **By section** — heatmap comparing application rates across class sections

**Filtering the cohort:**
- Use the **Quick filter** dropdown to jump to a specific criterion or check
- Use **Advanced filter** to build AND/OR/NOT conditions over check applied, option selected, class section, lab section, score ≥, or score ≤

**Drilling into submissions:**
Click any bar, option row, or table row to filter the submissions table below to only the students in that cohort. Use **Filter table to these N** to apply the current full filter. Clear the filter with the **Clear filter** button that appears above the table.

**Saving a shared default view:**
Instructors can save the current filter + visualization as the shared default for all staff with **Save as default**. All staff see this view when they open the dashboard. The provenance (saved by whom, when) is shown below the filter controls. Staff can reset to the saved default at any time.

**Exporting:**
Click **Export CSV** to download the current rubric breakdown (cohort + selected checks + visualization) as a CSV file.

### Submissions table

The submissions table lists every student who has made a submission. Per-row actions include releasing or unreleasing individual grades. Select multiple rows to release or unrelease in bulk.

When a rubric-report cohort filter is active, the table is restricted to matching students. Clear the filter to return to all submissions.

<Note>
Only students who have made a submission appear in the table. To see every student's repository (including those who haven't submitted), visit the **Repository Status** page.
</Note>

### Export controls

**Export grades** and **Download all** buttons appear in the assignment page header (instructor-only). These apply to the whole assignment rather than a filtered subset.

## Filtering and Sorting

Customize your dashboard view:

- Filter score statistics by class section or lab section using the dropdown in the Score statistics header.
- Filter the submissions table by grader, submission status, or rubric-report cohort.
- Sort by score, submission time, student name, or grading progress.

## Using the Dashboard

### Monitoring student progress

1. Review score statistics to understand class-wide performance.
2. Use the rubric breakdown to identify which checks are applied most or least frequently.
3. Filter by section to compare performance across lab or class sections.
4. Drill into a specific check to see which students received that feedback.

### Managing grading workflows

1. Use **Finalize grading** to mark all eligible reviews complete in one action.
2. Use **Release all** to publish grades to students once grading is done.
3. Use **Unrelease all** if you need to make corrections after release.
4. Select individual rows to release or unrelease specific submissions.

### Analyzing rubric patterns

1. Open the **Rubric breakdown** section.
2. Switch to **By section** to compare check application rates across sections.
3. Save a useful filter as the shared default so all graders see the same view.
4. Export the breakdown as CSV for further analysis.

## Best Practices

- **Check regularly**: Review the dashboard at least weekly to stay informed.
- **Save a default view**: Set a rubric breakdown filter that reflects your grading priorities so all staff start from the same context.
- **Use cohort drill-down**: Click a rubric check bar to quickly find students who received (or didn't receive) specific feedback.
- **Finalize before releasing**: Use **Finalize grading** to batch-complete eligible reviews, then **Release all** to publish grades in one step.

<Tip>
Click any bar in the rubric breakdown to filter the submissions table to just the students in that cohort — useful for targeted follow-up or re-grading.
</Tip>
