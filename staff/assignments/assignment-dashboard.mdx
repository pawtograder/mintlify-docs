# Assignment Dashboard

The assignment dashboard provides a centralized view of all key metrics and information for an assignment. Use this dashboard to monitor student progress, track submissions, manage grading workflows, and analyze rubric application patterns.

## Accessing the Dashboard

Navigate to any assignment to view its dashboard — it is the default landing page for each assignment. The dashboard has two tabs:

- **Dashboard** — score statistics, rubric breakdown, grading controls, and the submissions table.
- **Grading assigned to me** — your personal queue of pending review assignments.

## Dashboard Components

### Grading status panel

The top of the dashboard shows a summary of grading progress and provides assignment-level grading actions:

- **Graded / Released counts** — how many submissions have completed reviews and how many have been released to students.
- **Finalize grading** — marks every eligible submission review complete in one step. Only reviews that satisfy all required rubric checks are finalized; reviews with missing required checks are skipped. A preview shows how many reviews will be affected before you confirm.
- **Release all** — makes grades visible to all students for every submission in the assignment.
- **Unrelease all** — hides grades from all students (reverses Release all).

### Score statistics

The score statistics section shows min, max, and average scores with sparkline histograms for:

- **Total score** — the combined autograder + hand-grading score.
- **Autograder score** — the automated test score alone.
- **Submissions per student** — how many times each student submitted.

Use the **Filter** dropdown to restrict statistics to a specific class section or lab section. Click **Show detailed distributions** to expand full-size histograms.

### Rubric breakdown

The collapsible **Rubric breakdown** panel shows how often each rubric check was applied across the cohort. Use it to:

- Identify checks that are applied very frequently or rarely.
- Filter the cohort by section, score range, or specific check combinations using the **Advanced filter** (AND/OR/NOT logic).
- Switch between **Bars**, **Options**, **Table**, and **By section** visualizations.
- Click any bar, option, or table row to filter the submissions table below to the students in that cohort.
- **Export CSV** to download the current view.

Instructors can click **Save as default** to persist the current filter and visualization as the shared default that all staff see when they open the dashboard. The saved view shows who saved it and when.

### Submissions table

The submissions table lists all students who have made at least one submission. Instructors can:

- Select submissions with checkboxes and use **Release** or **Unrelease** to act on the selection.
- Filter by grader, section, score, and other columns.
- Export grades or download all submissions from the page header.

When a rubric breakdown cohort filter is active, the table automatically restricts to the matching students. Click **Clear filter** to return to all submissions.

<Note>
Only students who have made a submission appear in the submissions table. To see every student's repository status, visit the **Repository Status** page.
</Note>

## Exporting Data

Export assignment data for further analysis or department records:

- **Export grades** — downloads a CSV of submission scores and grading details.
- **Download all** — downloads all submission files as a zip archive.

Both controls are available in the assignment page header.

## Integration with Other Features

The assignment dashboard integrates with:

- [Security Dashboard](/staff/assignments/security-dashboard): Academic integrity monitoring
- [Test Insights](/staff/assignments/test-insights): Student performance analytics
- [Grading Assignments](/staff/assignments/grading-assignments): Task distribution and management

<Tip>
Use the rubric breakdown's **By section** view to compare check application rates across class sections — a quick way to spot sections where students are struggling with specific criteria.
</Tip>
