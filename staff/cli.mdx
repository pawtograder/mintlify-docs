# Command Line Interface

The Pawtograder CLI is a command-line tool for instructors and site administrators to automate course management tasks. It provides programmatic access to Pawtograder's core functionality, enabling bulk operations, scripting, and integration with other tools.

## Installation

Install the CLI globally from npm:

```bash
npm install -g @pawtograder/cli
pawtograder --help
```

Or run it without installing:

```bash
npx @pawtograder/cli --help
```

Requires Node.js 20 or later.

<Note>
You can also run the CLI from a checkout of the platform repository using `npm run cli -- <command>`.
</Note>

## Authentication

Before using the CLI, you must authenticate with an API token.

### Creating an API token

1. Log in to Pawtograder.
2. Navigate to **Settings → API Tokens**.
3. Create a new token with the appropriate scopes:
   - `cli:read` — for read-only commands (list, show, export)
   - `cli:write` — for commands that change data (copy, import, delete, assign)
4. Copy the generated token. It starts with `mcp_`.

### Logging in

```bash
# Interactive login (prompts for token)
pawtograder login

# Login with token directly (for scripts and CI)
pawtograder login --token mcp_your_token_here
```

The token is stored in `~/.pawtograder/credentials.json`.

For self-hosted deployments, point `--url` at your deployment's **API gateway origin** (not the web host):

```bash
pawtograder login --url https://api.your-school.edu
```

### Managing authentication

```bash
# Check current user
pawtograder whoami

# Log out
pawtograder logout
```

## Available commands

### Classes

```bash
# List all classes your token can see
pawtograder classes list

# Show details for a specific class
pawtograder classes show <id-or-slug>
```

### Assignments

```bash
# List assignments for a class
pawtograder assignments list --class <identifier>

# Show assignment details
pawtograder assignments show <identifier> --class <identifier>

# Copy assignments between classes
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --all

# Copy with schedule (CSV file with dates)
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --schedule <file.csv>

# Delete an assignment
pawtograder assignments delete <identifier> \
  --class <identifier> \
  --force
```

#### Assignment copy options

| Option | Description |
|--------|-------------|
| `--assignment <slug>` | Copy a single assignment |
| `--all` | Copy all assignments from source class |
| `--schedule <file>` | Copy assignments with date overrides from CSV |
| `--dry-run` | Preview changes without making them |
| `--skip-repos` | Skip repository operations |
| `--skip-rubrics` | Skip rubric copying |
| `--skip-surveys` | Skip survey copying |
| `--workdir <path>` | Local directory for git clones (required for repo operations) |
| `--concurrency <n>` | Parallel operations (1–8, default 4) |
| `--delay-ms <ms>` | Delay between clone batches in milliseconds |

### Submissions

```bash
# List submissions with scores for an assignment
pawtograder submissions list \
  --class <identifier> \
  --assignment <identifier>

# Include students who have not submitted
pawtograder submissions list \
  --class <identifier> \
  --assignment <identifier> \
  --include-non-submitters

# Output as JSON (pipe to jq)
pawtograder submissions list \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --json | jq '.submissions[] | select(.student_total_score == null)'
```

#### Import or sync comments

```bash
# Add-only import
pawtograder submissions comments import \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync (insert new + soft-delete missing)
pawtograder submissions comments sync \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --rubric-part-id <id>
```

#### Import artifacts

```bash
pawtograder submissions artifacts import \
  --class <identifier> \
  --assignment <identifier> \
  --file manifest.json \
  --overwrite
```

### Reviews

```bash
# List review assignments
pawtograder reviews list \
  --class <identifier> \
  --assignment <identifier>

# Filter by status
pawtograder reviews list \
  --class <identifier> \
  --assignment <identifier> \
  --status pending
```

#### Assigning grading work

`reviews assign` distributes submissions across active graders and instructors, balancing load round-robin. It honors `grading_conflicts` and never assigns someone their own submission.

```bash
# Preview a balanced split (dry run)
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --due-date 2026-09-15 \
  --dry-run

# Create assignments
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --due-date 2026-09-15

# One assignment per rubric part
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --due-date 2026-09-15 \
  --by-part

# Restrict to specific graders
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --due-date 2026-09-15 \
  --grader <profile-id> \
  --grader <profile-id>
```

For allocations the round-robin cannot express, supply an explicit manifest:

```json
[{ "assignee_profile_id": "…", "submission_id": 123, "rubric_part_id": 45 }]
```

```bash
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw-1 \
  --due-date 2026-09-15 \
  --file drafts.json
```

Re-running is safe: existing assignments are reused rather than duplicated.

A bare `--due-date` (for example, `2026-09-15`) means the **end of that day in the class's time zone**. Append a time (`2026-09-15T17:00`) for a specific time, or pass a timestamp with an offset to bypass the class zone.

### Help requests

```bash
# List help requests (all statuses)
pawtograder help-requests list --class <identifier>

# Show only active (open or in-progress) requests
pawtograder help-requests list --class <identifier> --status active

# Close a help request
pawtograder help-requests close --id <id>

# Close with resolution details
pawtograder help-requests close \
  --id <id> \
  --status resolved \
  --resolution-status staff_helped \
  --notes "Helped with null pointer exception"
```

### Rubrics

```bash
# List rubrics for an assignment
pawtograder rubrics list \
  --assignment <identifier> \
  --class <identifier>

# Export rubric to YAML
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --type grading \
  --output hw1-rubric.yml

# Export as a template (strips database IDs so import creates new rows)
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --type grading \
  --strip-ids \
  --output hw1-template.yml

# Preview a rubric import
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading \
  --dry-run

# Apply a rubric import
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading
```

Rubric types: `grading`, `self_review`, `meta`

## Repository maintenance

Repository commands use local SSH git operations. They require SSH access to GitHub and a writable `--workdir`.

### List repositories

```bash
pawtograder repos list \
  --class <identifier> \
  --assignment <identifier>
```

### Sync grade workflow

Sync `.github/workflows/grade.yml` from handout to all student repos:

```bash
pawtograder repos sync-grade-workflow \
  --class <identifier> \
  --assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview changes only
- `--concurrency <n>`: Parallel operations (1–8, default 2)
- `--delay-ms <ms>`: Delay between batches

### Cross-assignment copy

Copy files from source assignment repos to target assignment repos after source due date:

```bash
pawtograder repos copy-after-source-due \
  --class <identifier> \
  --source-assignment <identifier> \
  --target-assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview with rsync -n only
- `--mirror-delete`: Pass rsync --delete (excludes .git)
- `--concurrency <n>`: Parallel operations (1–8, default 2)

## JSON output

Every `list` command accepts `--json` to emit the raw API response instead of a formatted table. This is useful for scripting:

```bash
# Find students without a score
pawtograder submissions list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.submissions[] | select(.student_total_score == null)'

# Count pending reviews
pawtograder reviews list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.summary.pending'
```

## Environment variables

| Variable | Effect |
|----------|--------|
| `PAWTOGRADER_HTTP_TIMEOUT_MS` | Abort requests after this many milliseconds. Unset means no timeout. Raise it for large artifact imports. |
| `PAWTOGRADER_VERBOSE=1` | Log each request and its timing to stderr. |
| `DEBUG=1` | Same as above, plus stack traces on unexpected errors. |

The CLI does not read `.env` files.

## Best practices

1. **Use dry-run mode**: Always test with `--dry-run` before running destructive operations.
2. **Backup data**: Export important data before making bulk changes.
3. **Use workdir**: Specify a dedicated working directory for git operations to avoid conflicts.
4. **Secure tokens**: Store API tokens securely and never commit them to version control.
5. **Use specific identifiers**: Prefer slugs or IDs over names for reliability.

## Troubleshooting

### Authentication issues

If you encounter authentication errors:

1. Verify your token is valid: `pawtograder whoami`
2. Check token scopes match the required permissions (`cli:read` or `cli:write`)
3. For self-hosted deployments, ensure `--url` points to the API gateway origin (for example, `https://api.your-school.edu`), not the web host

### Repository operations

If git operations fail:

1. Ensure you have SSH access to GitHub: `ssh -T git@github.com`
2. Verify the workdir has sufficient disk space
3. Try reducing `--concurrency` for rate-limited operations

### Timeout errors

For large operations:

1. Set a longer timeout: `PAWTOGRADER_HTTP_TIMEOUT_MS=600000 pawtograder ...`
2. Use smaller batch sizes for artifact imports
3. Use `--dry-run` first to validate before running the full operation
