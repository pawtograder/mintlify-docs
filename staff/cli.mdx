# Command Line Interface

The Pawtograder CLI (`@pawtograder/cli`) is a command-line tool for instructors and site administrators to automate course management tasks. It provides programmatic access to Pawtograder's core functionality, enabling bulk operations, scripting, and integration with other tools.

## Installation

Run without installing:

```bash
npx @pawtograder/cli --help
```

Or install globally to get the `pawtograder` command:

```bash
npm install -g @pawtograder/cli
pawtograder --help
```

Requires Node.js 20 or later.

You can also run the CLI from a checkout of the platform repository:

```bash
npm run cli -- <command> [options]
```

## Authentication

Before using the CLI, you must authenticate with an API token.

### Creating an API token

1. Log in to Pawtograder
2. Navigate to **Settings → API Tokens**
3. Create a token with the `cli:read` scope for read commands, or `cli:write` for commands that change data
4. Copy the generated token

### Logging in

```bash
# Interactive login (prompts for token)
pawtograder login

# Login with token directly
pawtograder login --token YOUR_TOKEN_HERE
```

The token is stored in `~/.pawtograder/credentials.json`. For scripts and CI, pass it directly with `--token`.

### Self-hosted deployments

Point `--url` at your deployment's **API gateway origin**, not the web host:

```bash
pawtograder login --url https://api.your-school.edu
```

The web host serves the application; the CLI talks to the `cli` Edge Function behind the API origin. Passing the web host produces an HTML response and the CLI will tell you so.

### Managing authentication

```bash
# Check current user
pawtograder whoami

# Log out
pawtograder logout
```

## Available commands

Add `--help` to any command or group for its full options. Every `list` command accepts `--json` to emit the raw API response for piping into `jq`.

### Classes

```bash
# List classes your token can see
pawtograder classes list [--json]

# Show a single class
pawtograder classes show <id>
```

### Assignments

```bash
# List assignments for a class
pawtograder assignments list --class <identifier> [--json]

# Show assignment details
pawtograder assignments show <identifier> --class <identifier>

# Copy assignments between classes
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --all [--dry-run]

# Copy with a date schedule (CSV file)
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --schedule <file.csv>

# Delete an assignment
pawtograder assignments delete <identifier> \
  --class <identifier> \
  --force
```

### Submissions

```bash
# List submissions for an assignment (roster with scores)
pawtograder submissions list \
  --class <identifier> \
  --assignment <identifier> \
  [--include-non-submitters] [--json]

# Export submission files
pawtograder submissions export \
  --class <identifier> \
  --assignment <identifier>

# Import batch comments
pawtograder submissions comments import \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync comments (insert + soft-delete missing)
pawtograder submissions comments sync \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --rubric-part-id <id>

# Import artifacts
pawtograder submissions artifacts import \
  --class <identifier> \
  --assignment <identifier> \
  --file manifest.json [--overwrite]
```

### Reviews

```bash
# List review assignments
pawtograder reviews list \
  --class <identifier> \
  --assignment <identifier> \
  [--status pending|completed|all] [--json]

# Create review assignments (balanced round-robin)
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  [--by-part] [--dry-run]

# Restrict the grader pool
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --grader <profile-id> --grader <profile-id>

# Supply an explicit manifest instead of round-robin
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --file drafts.json
```

`reviews assign` balances submissions across active graders and instructors, honoring `grading_conflicts` and never assigning someone their own submission. A bare `--due-date` (e.g. `2026-09-15`) means end of that day in the class's time zone. Append a time (`2026-09-15T17:00`) for something specific.

Re-running is safe: existing assignments are reused rather than duplicated.

### Discussions

```bash
# List discussion topics with thread and question counts
pawtograder discussions list --class <identifier> [--json]
```

### Help requests

```bash
# List the office-hours help queue
pawtograder help-requests list \
  --class <identifier> \
  [--status open|in_progress|resolved|closed|active|all] \
  [--queue <id|name>] [--json]

# Close or resolve a help request (instructors only)
pawtograder help-requests close \
  --id <id> \
  [--status closed|resolved] \
  [--resolution-status staff_helped|self_solved|peer_helped|no_time|other] \
  [--notes "..."]
```

### Rubrics

```bash
# List rubrics for an assignment
pawtograder rubrics list \
  --assignment <identifier> \
  --class <identifier> [--json]

# Export rubric to YAML
pawtograder rubrics export \
  --assignment <identifier> \
  --class <identifier> \
  --type grading \
  --output rubric.yml [--strip-ids]

# Import rubric from YAML (with dry-run preview)
pawtograder rubrics import \
  --assignment <identifier> \
  --class <identifier> \
  --file rubric.yml \
  --type grading [--dry-run]
```

Rubric types: `grading`, `self_review`, `meta`

Use `--strip-ids` on export to produce a template that creates all rows fresh on import (useful for copying a rubric structure to a new assignment).

### Surveys

```bash
# Copy all surveys between classes
pawtograder surveys copy \
  --source-class <slug> \
  --target-class <slug> \
  --all

# Copy a single survey
pawtograder surveys copy \
  --source-class <slug> \
  --target-class <slug> \
  --survey <uuid|title>
```

### Flashcards

```bash
# List flashcard decks
pawtograder flashcards list --class <identifier> [--json]

# Copy all decks between classes
pawtograder flashcards copy \
  --source-class <slug> \
  --target-class <slug> \
  --all
```

## Repository maintenance

These commands run **git on your machine over SSH**, not on the server. They require a writable `--workdir` and working GitHub SSH access.

```bash
# List student repositories for an assignment
pawtograder repos list \
  --class <identifier> \
  --assignment <identifier> [--json]

# Sync grade.yml from handout to all student repos
pawtograder repos sync-grade-workflow \
  --class <identifier> \
  --assignment <identifier> \
  --workdir <path> [--dry-run]

# Copy files from source repos to target repos after source due date
pawtograder repos copy-after-source-due \
  --class <identifier> \
  --source-assignment <identifier> \
  --target-assignment <identifier> \
  --workdir <path> [--dry-run]
```

## Environment variables

All optional.

| Variable | Effect |
|---|---|
| `PAWTOGRADER_HTTP_TIMEOUT_MS` | Abort requests after this many milliseconds. Unset means no timeout. |
| `PAWTOGRADER_VERBOSE=1` | Log each request and its timing to stderr. |
| `DEBUG=1` | Same as above, plus stack traces on unexpected errors. |

The CLI does not read `.env` files when installed globally.

## Common workflows

### Copy course to new semester

```bash
# Copy all assignments
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all --dry-run

# Copy surveys and flashcards
pawtograder surveys copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all

pawtograder flashcards copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all
```

### Assign grading work

```bash
# Preview a balanced split
pawtograder reviews assign \
  -c cs3500-fall-2026 -a hw-1 \
  --due-date 2026-09-15 --dry-run

# Create assignments, one per rubric part
pawtograder reviews assign \
  -c cs3500-fall-2026 -a hw-1 \
  --due-date 2026-09-15 --by-part
```

### Export and modify rubrics

```bash
# Export
pawtograder rubrics export \
  --assignment hw1 --class cs3500 \
  --type grading --output hw1-rubric.yml

# Edit hw1-rubric.yml locally, then preview changes
pawtograder rubrics import \
  --assignment hw1 --class cs3500 \
  --file hw1-rubric.yml --type grading --dry-run

# Apply
pawtograder rubrics import \
  --assignment hw1 --class cs3500 \
  --file hw1-rubric.yml --type grading
```

### Query submissions with jq

```bash
pawtograder submissions list \
  -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.submissions[] | select(.student_total_score == null)'
```

## Error handling

Use `--help` with any command for detailed usage:

```bash
pawtograder assignments --help
pawtograder reviews assign --help
```

## Best practices

1. **Use `--dry-run`** before running destructive or bulk operations
2. **Use `--json`** to pipe output into `jq` for filtering and scripting
3. **Use specific identifiers** — prefer slugs or IDs over names for reliability
4. **Secure tokens** — never commit API tokens to version control; use environment variables or `~/.pawtograder/credentials.json`
