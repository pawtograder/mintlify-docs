# Command Line Interface (Beta)

The Pawtograder CLI is a command-line tool for instructors and site administrators to automate course management tasks. It provides programmatic access to Pawtograder's core functionality, enabling bulk operations, scripting, and integration with other tools.

<Warning>
The CLI is currently in beta. Commands and options may change in future releases.
</Warning>

## Installation

Run the CLI without installing:

```bash
npx @pawtograder/cli --help
```

Or install globally to get the `pawtograder` command:

```bash
npm install -g @pawtograder/cli
pawtograder --help
```

Requires Node.js 20 or later.

## Authentication

Before using the CLI, authenticate with an API token.

### Creating an API token

1. Log in to Pawtograder.
2. Navigate to **Settings → API Tokens**.
3. Create a new token with the `cli:read` scope for read commands, or `cli:write` for commands that change data.
4. Copy the generated token (it starts with `mcp_`).

### Logging in

```bash
pawtograder login
```

The token is stored in `~/.pawtograder/credentials.json`. You can also pass it directly for scripts and CI:

```bash
pawtograder login --token mcp_your_token_here
```

For self-hosted deployments, point `--url` at your deployment's **API gateway origin**, not the web host:

```bash
pawtograder login --url https://api.your-school.edu
```

### Managing authentication

```bash
# Check current user
pawtograder whoami

# Log out
pawtograder logout
```

## Available commands

### Classes

```bash
# List all classes your token can see
pawtograder classes list

# Show details for a specific class
pawtograder classes show <id-or-slug>
```

### Assignments

```bash
# List assignments for a class
pawtograder assignments list --class <identifier>

# Show assignment details
pawtograder assignments show <identifier> --class <identifier>

# Copy assignments between classes
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all

# Copy with schedule (CSV file with dates)
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --schedule schedule.csv

# Delete an assignment
pawtograder assignments delete <identifier> \
  --class <identifier> \
  --force
```

#### Assignment copy options

- `--assignment <slug>`: Copy a single assignment
- `--all`: Copy all assignments from source class
- `--schedule <file>`: Copy assignments with date overrides from CSV
- `--dry-run`: Preview changes without making them
- `--skip-repos`: Skip repository operations
- `--skip-rubrics`: Skip rubric copying
- `--skip-surveys`: Skip survey copying
- `--workdir <path>`: Local directory for git clones (required for repo operations)
- `--concurrency <n>`: Parallel operations (1–8, default 4)
- `--delay-ms <ms>`: Delay between clone batches in milliseconds

### Submissions

List submissions for an assignment, with autograder and total scores:

```bash
pawtograder submissions list \
  --class cs3500-fall-2025 \
  --assignment hw1

# Include students who have not submitted
pawtograder submissions list \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --include-non-submitters

# Machine-readable output
pawtograder submissions list \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --json | jq '.submissions[] | select(.student_total_score == null)'
```

#### Import or sync comments

Batch import submission comments from autograder results:

```bash
# Add-only import
pawtograder submissions comments import \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync (insert new + soft-delete missing)
pawtograder submissions comments sync \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file batch-results.json \
  --rubric-part-id <id>
```

#### Import artifacts

Upload submission artifact blobs from a manifest:

```bash
pawtograder submissions artifacts import \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file manifest.json \
  --batch-size 5
```

Options: `--overwrite`, `--dry-run`, `--batch-size <n>` (default 5).

### Reviews

List and create grading review assignments:

```bash
# List review assignments
pawtograder reviews list \
  --class cs3500-fall-2025 \
  --assignment hw1

# Filter by status
pawtograder reviews list \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --status pending
```

#### Assigning grading work

`reviews assign` spreads submissions across active graders and instructors, balancing on how much each already holds. It honors `grading_conflicts` and never assigns someone their own submission.

```bash
# Preview a balanced split
pawtograder reviews assign \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --dry-run

# One assignment per rubric part
pawtograder reviews assign \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --by-part

# Restrict the grader pool
pawtograder reviews assign \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --grader <profile-id>
```

A bare `--due-date` (for example, `2026-09-15`) means the **end of that day in the class's time zone**. Append a time (`2026-09-15T17:00`) for a specific deadline.

For allocations the round-robin cannot express, supply an explicit manifest:

```bash
pawtograder reviews assign \
  --class cs3500-fall-2025 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --file drafts.json
```

The manifest is a JSON array of `{ "assignee_profile_id": "...", "submission_id": 123, "rubric_part_id": 45 }` objects. Re-running is safe: existing assignments are reused rather than duplicated.

### Help requests

```bash
# List all help requests
pawtograder help-requests list --class cs3500-fall-2025

# Show only active (open or in-progress) requests
pawtograder help-requests list \
  --class cs3500-fall-2025 \
  --status active

# Close a help request
pawtograder help-requests close --id <id>

# Close with resolution details
pawtograder help-requests close \
  --id <id> \
  --status resolved \
  --resolution-status staff_helped \
  --notes "Helped student debug their loop"
```

### Rubrics

```bash
# List rubrics for an assignment
pawtograder rubrics list \
  --assignment hw1 \
  --class cs3500-spring-2026

# Export rubric to YAML
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --type grading \
  --output hw1-rubric.yml

# Import rubric from YAML (with dry-run preview)
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading \
  --dry-run

# Apply the import
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading
```

Rubric types: `grading`, `self_review`, `meta`.

Use `--strip-ids` on export to create a template that imports as entirely new rows.

## Repository maintenance

Repository commands use local SSH git operations on your machine, not the server. They require a writable `--workdir` and working GitHub SSH access.

### List repositories

```bash
pawtograder repos list \
  --class cs3500-fall-2025 \
  --assignment hw1
```

### Sync grade workflow

Sync `.github/workflows/grade.yml` from the handout repository to all student repos:

```bash
pawtograder repos sync-grade-workflow \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --workdir ~/pawtograder-repos \
  --dry-run
```

Options: `--dry-run`, `--concurrency <n>` (1–8, default 2), `--delay-ms <ms>`.

### Cross-assignment copy

Copy files from source assignment repos to target assignment repos after the source due date:

```bash
pawtograder repos copy-after-source-due \
  --class cs3500-spring-2026 \
  --source-assignment hw1 \
  --target-assignment hw2 \
  --workdir ~/pawtograder-repos
```

Options: `--dry-run`, `--mirror-delete` (passes `rsync --delete`), `--concurrency <n>`.

## JSON output

Every `list` command accepts `--json` for machine-readable output:

```bash
pawtograder submissions list -c cs3500-fall-2025 -a hw1 --json | jq '.submissions[] | select(.student_total_score == null)'
pawtograder reviews list -c cs3500-fall-2025 -a hw1 --json | jq '.reviews[] | select(.review_completed_by_assignee == false)'
```

## Environment variables

All optional.

| Variable | Effect |
|----------|--------|
| `PAWTOGRADER_HTTP_TIMEOUT_MS` | Abort requests after this many milliseconds. Unset means no timeout. Raise it for large artifact imports. |
| `PAWTOGRADER_VERBOSE=1` | Log each request and its timing to stderr. |
| `DEBUG=1` | Same as above, plus stack traces on unexpected errors. |

## API token scopes

- `cli:read` – Read-only operations (list, show, export)
- `cli:write` – Write operations (copy, import, delete, assign)

### Copy course to new semester

```bash
# 1. Copy all assignments with repositories
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all \
  --workdir ~/pawtograder-repos

# 2. Copy surveys
pawtograder surveys copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all

# 3. Copy flashcard decks
pawtograder flashcards copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all
```

### Bulk update rubrics

```bash
# Export the current rubric
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500 \
  --type grading \
  --output hw1-rubric.yml

# Edit hw1-rubric.yml locally

# Preview changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml \
  --dry-run

# Apply changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml
```

### Assign grading for a homework

```bash
# Preview the allocation
pawtograder reviews assign \
  -c cs3500-spring-2026 \
  -a hw1 \
  --due-date 2026-09-15 \
  --dry-run

# Create the assignments
pawtograder reviews assign \
  -c cs3500-spring-2026 \
  -a hw1 \
  --due-date 2026-09-15
```

## Troubleshooting

### Authentication issues

If you see "Not logged in" or "Authentication failed":

1. Run `pawtograder login` to re-authenticate.
2. Verify your token is valid in the web UI (**Settings → API Tokens**).
3. Ensure your token has the correct scopes (`cli:read` or `cli:write`).

If you see an HTML response error, you are pointing at the web host instead of the API gateway. Use `--url https://api.<hostname>` when logging in.

### Repository operations

If git operations fail:

1. Verify SSH access: `ssh -T git@github.com`
2. Check that you're a member of the course's GitHub organization.
3. Retry with lower `--concurrency` (try 2 or 1).
4. Use `--delay-ms 1000` to add delays between batches.

### Timeout errors

For large operations:

1. Set a longer timeout: `PAWTOGRADER_HTTP_TIMEOUT_MS=600000 pawtograder ...`
2. Use smaller batch sizes (for example, `--batch-size 1` for artifact imports).
3. Use `--dry-run` first to validate before running the full operation.
