# Command Line Interface (Beta)

The Pawtograder CLI is a command-line tool for instructors and site administrators to automate course management tasks. It provides programmatic access to Pawtograder's core functionality, enabling bulk operations, scripting, and integration with other tools.

<Warning>
The CLI is currently in beta. Commands and options may change in future releases.
</Warning>

## Installation

Install the CLI from npm:

```bash
npm install -g @pawtograder/cli
pawtograder --help
```

Or run it without installing:

```bash
npx @pawtograder/cli --help
```

Requires Node.js 20 or later.

## Authentication

Before using the CLI, you must authenticate with an API token.

### Creating an API token

1. Log in to Pawtograder.
2. Navigate to **Settings → API Tokens**.
3. Create a new token with `cli:read` for read commands, or `cli:write` for commands that change data.
4. Copy the generated token (it starts with `mcp_`).

### Logging in

```bash
# Interactive login (prompts for token)
pawtograder login

# Login with token directly (for scripts and CI)
pawtograder login --token mcp_YOUR_TOKEN_HERE

# Login to a self-hosted instance
pawtograder login --url https://api.your-school.edu
```

Point `--url` at your deployment's **API gateway origin**, not the web host. The web host serves the application; the CLI talks to the `cli` Edge Function behind the API origin.

### Managing authentication

```bash
# Check current user
pawtograder whoami

# Log out
pawtograder logout
```

## Available commands

### Classes

```bash
# List all classes your token can see
pawtograder classes list
pawtograder classes list --json
```

### Assignments

```bash
# List assignments for a class
pawtograder assignments list --class <identifier>
pawtograder assignments list --class <identifier> --json

# Show assignment details
pawtograder assignments show <identifier> --class <identifier>

# Copy assignments between classes
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --all

# Copy with schedule (CSV file with dates)
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --schedule <file.csv>

# Delete an assignment
pawtograder assignments delete <identifier> \
  --class <identifier> \
  --force
```

#### Assignment copy options

- `--assignment <slug>`: Copy a single assignment
- `--all`: Copy all assignments from source class
- `--schedule <file>`: Copy assignments with date overrides from CSV
- `--dry-run`: Preview changes without making them
- `--skip-repos`: Skip repository operations
- `--skip-rubrics`: Skip rubric copying
- `--skip-surveys`: Skip survey copying
- `--workdir <path>`: Local directory for git clones (required for repo operations)
- `--concurrency <n>`: Parallel operations (1-8, default 4)
- `--delay-ms <ms>`: Delay between clone batches in milliseconds

### Submissions

List submissions with autograder and total scores:

```bash
pawtograder submissions list --class <identifier> --assignment <identifier>
pawtograder submissions list --class <identifier> --assignment <identifier> --json
```

Options:
- `--include-non-submitters` — also list enrolled students who have not submitted
- `--limit <n>` — maximum rows to return (default 1000)

Import comments and artifacts:

```bash
# Import submission comments
pawtograder submissions comments import \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync comments (insert + soft-delete missing)
pawtograder submissions comments sync \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --rubric-part-id <id>

# Import artifacts
pawtograder submissions artifacts import \
  --class <identifier> \
  --assignment <identifier> \
  --file manifest.json \
  --overwrite
```

### Reviews

List review assignments:

```bash
pawtograder reviews list --class <identifier> --assignment <identifier>
pawtograder reviews list --class <identifier> --assignment <identifier> --status pending
```

Assign grading work across staff, balanced round-robin:

```bash
# Preview a balanced split
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --dry-run

# One assignment per rubric part
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --by-part

# Explicit manifest
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --file drafts.json
```

`reviews assign` honors `grading_conflicts` and never assigns someone their own submission. Re-running is safe — existing assignments are reused rather than duplicated.

A bare `--due-date` is the end of that day in the class's time zone. Append a time (`2026-09-15T17:00`) for a specific time.

### Help requests

```bash
# List help requests
pawtograder help-requests list --class <identifier>
pawtograder help-requests list --class <identifier> --status active

# Close or resolve a request (instructors only)
pawtograder help-requests close --id <id>
pawtograder help-requests close --id <id> --status resolved --resolution-status staff_helped
```

### Discussions

```bash
pawtograder discussions list --class <identifier>
pawtograder discussions list --class <identifier> --json
```

### Rubrics

```bash
# List rubrics for an assignment
pawtograder rubrics list \
  --assignment <identifier> \
  --class <identifier>

# Export rubric to YAML
pawtograder rubrics export \
  --assignment <identifier> \
  --class <identifier> \
  --type grading \
  --output rubric.yml

# Export as a template (no database IDs)
pawtograder rubrics export \
  --assignment <identifier> \
  --class <identifier> \
  --type grading \
  --strip-ids \
  --output rubric-template.yml

# Import rubric from YAML (dry-run first)
pawtograder rubrics import \
  --assignment <identifier> \
  --class <identifier> \
  --file rubric.yml \
  --type grading \
  --dry-run

# Apply import
pawtograder rubrics import \
  --assignment <identifier> \
  --class <identifier> \
  --file rubric.yml \
  --type grading
```

Rubric types: `grading`, `self_review`, `meta`

### Surveys

## Repository maintenance

The CLI provides local git/rsync workflows for student repository operations. These commands fetch metadata from the API and perform git operations via SSH on your machine.

### Sync grade workflow

Sync `.github/workflows/grade.yml` from handout to all student repos:

```bash
pawtograder repos sync-grade-workflow \
  --class <identifier> \
  --assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview changes only
- `--concurrency <n>`: Parallel operations (1-8, default 2)
- `--delay-ms <ms>`: Delay between batches

### Cross-assignment copy

Copy files from source assignment repos to target assignment repos after source due date:

```bash
pawtograder repos copy-after-source-due \
  --class <identifier> \
  --source-assignment <identifier> \
  --target-assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview with rsync -n only
- `--mirror-delete`: Pass rsync --delete (excludes .git)
- `--concurrency <n>`: Parallel operations (1-8, default 2)

## JSON output

Every `list` command accepts `--json` to emit the raw API response instead of a formatted table. This is useful for scripting:

```bash
# Find students without a submission
pawtograder submissions list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.submissions[] | select(.student_total_score == null)'

# Count pending reviews
pawtograder reviews list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.summary.pending'
```

## Environment variables

- `PAWTOGRADER_HTTP_TIMEOUT_MS`: HTTP timeout in milliseconds (unset means no timeout)
- `PAWTOGRADER_VERBOSE=1`: Log each request and its timing to stderr
- `DEBUG=1`: Verbose logging plus stack traces on unexpected errors

The CLI does not read `.env` files.

## Common workflows

### Copy course to new semester

```bash
# 1. Copy all assignments with repositories
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all \
  --workdir ~/pawtograder-repos

# 2. Copy surveys
pawtograder surveys copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all

# 3. Copy flashcard decks
pawtograder flashcards copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all
```

### Assign and track grading

```bash
# Assign reviews balanced across all graders
pawtograder reviews assign \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --dry-run

# Check completion
pawtograder reviews list \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --status pending \
  --json | jq '.summary'
```

### Export and modify rubrics

```bash
# Export rubric
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500 \
  --type grading \
  --output hw1-rubric.yml

# Edit hw1-rubric.yml locally

# Preview changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml \
  --type grading \
  --dry-run

# Apply
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml \
  --type grading
```

### Bulk update grade workflows

```bash
pawtograder repos sync-grade-workflow \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --workdir ~/pawtograder-repos \
  --concurrency 4
```

## Error handling

The CLI provides detailed error messages and exit codes:

- `0`: Success
- `1`: General error
- `2`: Authentication error
- `3`: Not found error
- `4`: Validation error

Use `--help` with any command to see detailed usage information:

```bash
pawtograder assignments --help
pawtograder assignments copy --help
pawtograder reviews assign --help
```

## Best practices

1. **Use dry-run mode**: Always test with `--dry-run` before running destructive operations
2. **Backup data**: Export important data before making bulk changes
3. **Use workdir**: Specify a dedicated working directory for git operations to avoid conflicts
4. **Monitor progress**: The CLI provides detailed logging for long-running operations
5. **Secure tokens**: Store API tokens securely and never commit them to version control
6. **Use specific identifiers**: Prefer slugs or IDs over names for reliability

## Troubleshooting

### Authentication issues

If you encounter authentication errors:

1. Verify your token is valid: `pawtograder whoami`
2. Check token scopes match the required permissions (`cli:read` or `cli:write`)
3. For self-hosted deployments, ensure `--url` points to the API gateway origin (`https://api.<hostname>`), not the web host

### Repository operations

If git operations fail:

1. Ensure you have SSH access to GitHub
2. Verify the workdir has sufficient disk space
3. Check network connectivity
4. Try reducing `--concurrency` for rate-limited operations

### Performance

For large operations:

- Use `--concurrency` to control parallel operations
- Add `--delay-ms` to avoid rate limiting
- Consider running operations during off-peak hours
- Set `PAWTOGRADER_HTTP_TIMEOUT_MS=600000` for operations that may take more than a minute
