# Command Line Interface

The Pawtograder CLI is a command-line tool for instructors and site administrators to automate course management tasks. It provides programmatic access to Pawtograder's core functionality, enabling bulk operations, scripting, and integration with other tools.

## Installation

Install the CLI from npm:

```bash
npm install -g @pawtograder/cli
```

Or run it without installing:

```bash
npx @pawtograder/cli --help
```

Requires Node.js 20 or later.

## Authentication

Before using the CLI, you must authenticate with an API token.

### Creating an API Token

1. Log in to Pawtograder
2. Navigate to your account settings
3. Go to the "API Tokens" section
4. Click "Create New Token"
5. Give your token a descriptive name and select appropriate scopes
6. Copy the generated token (you won't be able to see it again)

### Logging in

```bash
# Interactive login (prompts for token)
pawtograder login

# Login with token directly
pawtograder login --token mcp_YOUR_TOKEN_HERE

# Login to a self-hosted instance (point at the API gateway origin, not the web host)
pawtograder login --url https://api.your-school.edu
```

Credentials are stored in `~/.pawtograder/credentials.json`.

### Managing authentication

```bash
# Check current user
pawtograder whoami

# Log out
pawtograder logout
```

## Available commands

### Classes

```bash
# List all classes you have access to
pawtograder classes list

# Show details for a specific class
pawtograder classes show <id-or-slug>
```

### Assignments

```bash
# List assignments for a class
pawtograder assignments list --class <identifier>

# Show assignment details
pawtograder assignments show <identifier> --class <identifier>

# Copy assignments between classes
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --all

# Copy with schedule (CSV file with dates)
pawtograder assignments copy \
  --source-class <slug> \
  --target-class <slug> \
  --schedule <file.csv>

# Delete an assignment
pawtograder assignments delete <identifier> \
  --class <identifier> \
  --force
```

#### Assignment copy options

- `--assignment <slug>`: Copy a single assignment
- `--all`: Copy all assignments from source class
- `--schedule <file>`: Copy assignments with date overrides from CSV
- `--dry-run`: Preview changes without making them
- `--skip-repos`: Skip repository operations
- `--skip-rubrics`: Skip rubric copying
- `--skip-surveys`: Skip survey copying
- `--workdir <path>`: Local directory for git clones (required for repo operations)
- `--concurrency <n>`: Parallel operations (1-8, default 4)
- `--delay-ms <ms>`: Delay between clone batches in milliseconds

### Rubrics

Import and export rubrics in YAML format:

```bash
# List rubrics for an assignment
pawtograder rubrics list \
  --assignment <identifier> \
  --class <identifier>

# Export rubric to YAML
pawtograder rubrics export \
  --assignment <identifier> \
  --class <identifier> \
  --type grading \
  --output rubric.yml

# Export as a template (strips database IDs so importing creates all rows fresh)
pawtograder rubrics export \
  --assignment <identifier> \
  --class <identifier> \
  --type grading \
  --strip-ids \
  --output rubric-template.yml

# Preview an import without making changes
pawtograder rubrics import \
  --assignment <identifier> \
  --class <identifier> \
  --file rubric.yml \
  --type grading \
  --dry-run

# Import rubric from YAML
pawtograder rubrics import \
  --assignment <identifier> \
  --class <identifier> \
  --file rubric.yml \
  --type grading
```

Rubric types: `grading`, `self_review`, `meta`

### Submissions

```bash
# List submissions with autograder and total scores
pawtograder submissions list \
  --class <identifier> \
  --assignment <identifier>

# Include students who have not submitted
pawtograder submissions list \
  --class <identifier> \
  --assignment <identifier> \
  --include-non-submitters

# Import submission comments
pawtograder submissions comments import \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync comments (insert + soft-delete missing)
pawtograder submissions comments sync \
  --class <identifier> \
  --assignment <identifier> \
  --file batch-results.json \
  --rubric-part-id <id>

# Import artifacts
pawtograder submissions artifacts import \
  --class <identifier> \
  --assignment <identifier> \
  --file manifest.json \
  --overwrite
```

### Reviews

```bash
# List review assignments
pawtograder reviews list \
  --class <identifier> \
  --assignment <identifier>

# Filter by status (pending, completed, all)
pawtograder reviews list \
  --class <identifier> \
  --assignment <identifier> \
  --status pending

# Create review assignments (balanced round-robin, preview first)
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15 \
  --dry-run

# Create assignments
pawtograder reviews assign \
  --class <identifier> \
  --assignment <identifier> \
  --due-date 2026-09-15
```

The allocator honors `grading_conflicts` and never assigns someone their own submission. A bare `--due-date` means end of that day in the class's time zone. Re-running is safe: existing assignments are reused rather than duplicated.

### Help requests

```bash
# List help requests
pawtograder help-requests list --class <identifier>

# Filter by status (open, in_progress, resolved, closed, active, all)
pawtograder help-requests list --class <identifier> --status active

# Close or resolve a help request (instructors only)
pawtograder help-requests close --id <id> --status resolved \
  --resolution-status staff_helped \
  --notes "Helped student debug their loop"
```

### Discussions

```bash
# List discussion topics with thread and question counts
pawtograder discussions list --class <identifier>
```

### Surveys

```bash
# Copy all surveys
pawtograder surveys copy \
  --source-class <slug> \
  --target-class <slug> \
  --all

# Copy single survey
pawtograder surveys copy \
  --source-class <slug> \
  --target-class <slug> \
  --survey <uuid|title>

# Link to target assignment
pawtograder surveys copy \
  --source-class <slug> \
  --target-class <slug> \
  --all \
  --target-assignment <slug>
```

### Flashcards

```bash

  --all

# Copy single deck
pawtograder flashcards copy \
```

## Repository maintenance

The CLI provides local git/rsync workflows for student repository operations. These commands fetch metadata from the API and perform git operations via SSH on your machine.

### List repositories

```bash
pawtograder repos list \
  --class <identifier> \
  --assignment <identifier>
```

### Sync grade workflow

Sync `.github/workflows/grade.yml` from handout to all student repos:

```bash
pawtograder repos sync-grade-workflow \
  --class <identifier> \
  --assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview changes only
- `--concurrency <n>`: Parallel operations (1-8, default 2)
- `--delay-ms <ms>`: Delay between batches

### Cross-assignment copy

Copy files from source assignment repos to target assignment repos after source due date:

```bash
pawtograder repos copy-after-source-due \
  --class <identifier> \
  --source-assignment <identifier> \
  --target-assignment <identifier> \
  --workdir <path>
```

Options:
- `--dry-run`: Preview with rsync -n only
- `--mirror-delete`: Pass rsync --delete (excludes .git)
- `--concurrency <n>`: Parallel operations (1-8, default 2)

## JSON output

Every `list` command accepts `--json` for machine-readable output:

```bash
pawtograder submissions list -c cs3500-fall-2026 -a hw-1 --json | jq '.submissions[] | select(.autograder_score == null)'
```

| Variable | Description |

| `PAWTOGRADER_VERBOSE=1` | Alternative verbose flag |

## Common workflows

### Copy course to new semester

```bash
# 1. Copy all assignments with repositories
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all \
  --workdir ~/pawtograder-repos

# 2. Copy surveys
pawtograder surveys copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all

# 3. Copy flashcard decks
pawtograder flashcards copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all
```

### Bulk update grade workflows

```bash
pawtograder repos sync-grade-workflow \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --workdir ~/pawtograder-repos \
  --concurrency 4
```

### Export and modify rubrics

```bash
# Export rubric
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500 \
  --type grading \
  --output hw1-rubric.yml

# Edit hw1-rubric.yml locally

# Preview changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml \
  --type grading \
  --dry-run

# Apply changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500 \
  --file hw1-rubric.yml \
  --type grading
```

### Assign grading work

```bash
# Preview a balanced split
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw1 \
  --due-date 2026-09-15 \
  --dry-run

# Create assignments
pawtograder reviews assign \
  --class cs3500-fall-2026 \
  --assignment hw1 \
  --due-date 2026-09-15
```

Use `--help` with any command to see detailed usage information:

```bash
pawtograder assignments --help
pawtograder assignments copy --help
```

## Best practices

1. **Use dry-run mode**: Always test with `--dry-run` before running destructive operations.
2. **Backup data**: Export important data before making bulk changes.
3. **Use workdir**: Specify a dedicated working directory for git operations to avoid conflicts.
4. **Secure tokens**: Store API tokens securely and never commit them to version control.
5. **Use specific identifiers**: Prefer slugs or IDs over names for reliability.

## Troubleshooting

### Authentication issues

If you encounter authentication errors:

1. Verify your token is valid: `pawtograder whoami`
2. Check token scopes match the required permissions (`cli:read` or `cli:write`).
3. Ensure you're connecting to the correct instance.

### Repository operations

If git operations fail:

1. Ensure you have SSH access to GitHub.
2. Verify the workdir has sufficient disk space.
3. Check network connectivity.
4. Try reducing `--concurrency` for rate-limited operations.

### Performance

For large operations:

- Use `--concurrency` to control parallel operations.
- Add `--delay-ms` to avoid rate limiting.
- Set `PAWTOGRADER_HTTP_TIMEOUT_MS=600000` for long-running imports.
