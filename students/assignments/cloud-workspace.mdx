# Cloud Workspace (Open in Coder)

Some courses provide a cloud workspace for each assignment: a browser-based VS Code environment that already has the course's toolchain installed and your assignment repository cloned. You do not need to install anything locally to use it.

<Note>
Cloud workspaces are only available when your instructor has enabled the **cloud-workspaces** feature for the course. If you do not see the workspace card on your assignment page, your course is not using this feature.
</Note>

## Opening your workspace

On the assignment page, find the **Open in Coder** card. It walks through three startup steps:

| Step | What it does |
| --- | --- |
| **Build** | Starts the workspace container. |
| **Clone** | Clones your assignment repository into the workspace. |
| **Editor** | Starts VS Code in the browser. |

Click **Open workspace** to start. The card shows which step is in progress. Once all three steps are complete, a link appears to open VS Code in a new tab.

## Linking your Forgejo account

Before your workspace can clone your repository, you need to link your Forgejo account to Coder. If the card shows a **Link Forgejo account** prompt, click it to open Coder's authorization page. After you authorize, return to the assignment page and the workspace will continue.

<Tip>
The link page opens in the same tab. Once you have authorized, come back to the assignment page and the workspace card will re-check your status automatically.
</Tip>

## If a step fails

If a step fails, the card names the step and shows a **Retry** button. Common causes:

- **Build failed** — The workspace container could not start. This may be a temporary resource issue. Try again in a few minutes.
- **Clone failed** — Your repository could not be cloned. Make sure your Forgejo account is linked (see above) and that your assignment repository exists.
- **Editor failed** — VS Code could not start. Retry usually resolves this.

If retrying does not help, contact your course staff.

## What happens when you restart

Your workspace has a persistent home volume. Files you create or edit in `/home/coder` survive a workspace restart. The workspace stops automatically after an hour of inactivity and restarts the next time you click **Open workspace**.

When the workspace restarts, the clone step checks whether your repository folder already exists and is a valid checkout of your assignment repository. If it is, the clone is skipped and VS Code opens directly. If the folder is missing or was not a finished clone, the repository is cloned again.

## Pushing your work

Your workspace is configured to push to your Forgejo repository using your linked Forgejo account. Use VS Code's Source Control panel or the terminal to commit and push as you normally would. Every push to the default branch is a submission, the same as pushing from your local machine.
