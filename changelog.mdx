This page covers changes since the end of the Spring 2026 term. Entries are grouped by month, newest first.

## September 2026

### September 10, 2026

#### GitHub

- **Deleted repositories no longer stall permission sync for an entire org** — A repository deleted outside Pawtograder previously caused its permission-sync job to spend 93 seconds on a retry ladder and then trip the org-wide circuit breaker, pausing syncs for every other course in the organization. The worker now probes whether the repository is genuinely gone before spending those retries, parks the row if it is, and keeps the failure isolated to that one repository ([#965](https://github.com/pawtograder/platform/pull/965))
- **Archived assignments excluded from permission sync and repo creation** — When a student's GitHub org membership is confirmed, the platform no longer queues permission-sync or repo-creation jobs for assignments that have been archived. Previously, archived assignments with deleted repos produced a stream of 404 errors and could trip the org-wide circuit breaker ([#965](https://github.com/pawtograder/platform/pull/965))

### September 9, 2026

#### Leaderboard

- **Leaderboard constraint no longer discards a student's grade** — A database check constraint on the leaderboard table (`autograder_score <= max_score`) was evaluated inside the same transaction as the autograder's feedback insert. When a grader legitimately produced a score above the declared maximum (for example, via mutation scoring), the constraint violation rolled back the entire grade. The constraint is removed, scores are clamped in a shared upsert function, and any future leaderboard error is logged as a warning rather than aborting grading ([#964](https://github.com/pawtograder/platform/pull/964))

### September 8, 2026

#### GitHub

- **Handout creation no longer fails for brand-new courses** — Creating the first mode-2 handout repository for a course with no enrolled students previously returned a 500 error because the student GitHub team did not exist yet. The platform now creates the team on demand during handout setup. Staff team grants are skipped gracefully when the staff team has not been created yet, matching the existing degradation behavior for the staff roster ([#959](https://github.com/pawtograder/platform/pull/959))

### September 7, 2026

#### GitHub

- **Permission sync performance improvements** — Repository permission sync was spending up to 63 seconds issuing removal requests that GitHub cannot honor (access held through a team or org ownership cannot be revoked via the direct-collaborator endpoint). Removals are now filtered to direct collaborators only. The org member list is also skipped when there are no users to add, saving up to 18 seconds on handout and solution repo creation. Expected sync time for a new handout repo drops from ~95 seconds to ~13 seconds ([#960](https://github.com/pawtograder/platform/pull/960))
- **Per-org permission sync exemptions** — Site admins can now configure a list of GitHub usernames that permission sync must never remove from repositories in a given org. This replaces a hardcoded list that applied to every org. The setting is available on the **GitHub Orgs** admin page ([#960](https://github.com/pawtograder/platform/pull/960))
- **Async worker drain concurrency and visibility timeout are now tunable** — The `github-async-worker` pgmq drain concurrency and visibility timeout can be configured via Helm values (`edgeFunctions.githubAsyncWorker.drainConcurrency` and `visibilityTimeoutSeconds`). Defaults reproduce the previous hardcoded behavior. The chart enforces that the visibility timeout and isolate lifetime cover the modeled batch size, and refuses incoherent combinations at render time ([#956](https://github.com/pawtograder/platform/pull/956))

#### Microsoft sign-in

- **Microsoft (Azure) sign-in now works** — The Helm chart was missing the required `GOTRUE_EXTERNAL_AZURE_REDIRECT_URI` environment variable, causing all Microsoft sign-in attempts to fail with a 400 error before contacting Microsoft. The redirect URI now defaults to the API gateway origin and can be overridden per deployment. An optional `url` field supports tenant pinning ([#957](https://github.com/pawtograder/platform/pull/957))

#### Bug fixes

- **Webhook provisioning retries no longer flood error alerts** — During a large assignment release, every repository's first webhook delivery arrived before provisioning finished, producing one error-level Sentry event per delivery per repository. These expected retries are now reported at `info` level with their own fingerprint, while genuine readiness failures remain at `error` level ([#955](https://github.com/pawtograder/platform/pull/955))
- **Discord discussion stats no longer silently fail on large batches** — The hourly Discord stats sync was putting all author UUIDs in a single database filter, which exceeded the URL length limit on batches of ~280 or more messages. The failure was swallowed and the summary reported `0 errors`. Author lookups are now chunked, failed chunks are counted as errors, and messages with unresolved authors are left for the next run rather than attributed to the wrong author ([#955](https://github.com/pawtograder/platform/pull/955))

## August 2026

### August 19, 2026

#### Surveys
- **Stricter rules on survey responses** — Responses are now accepted only for published surveys that are available, not deleted, and assigned to you, and only from members of the course. Editing a submitted response is refused when the survey does not allow response editing. Late responses are still accepted, as before

### August 12, 2026

#### Bug fixes
- **Preview as student stays on its own assignment** — On the **Test Assignment** page, **Preview as student** no longer shows submissions from other assignments ([#918](https://github.com/pawtograder/platform/pull/918))
- **Discord role sync scoped to active courses** — Role synchronization now runs only for active courses and stops retrying failures that cannot succeed ([#924](https://github.com/pawtograder/platform/pull/924))
- **Long-idle tabs no longer crash** — Returning to a Pawtograder tab left open for a long time no longer errors out when you come back to it ([#902](https://github.com/pawtograder/platform/pull/902))

### August 11, 2026

#### Grading and gradebook
- **Safeguards on scores and completion** — Rubric point values are rejected if they are negative, grading completion is computed from each student's own reviews rather than an assignment-wide summary, and an out-of-date gradebook recalculation can no longer overwrite newer grades ([#922](https://github.com/pawtograder/platform/pull/922))

### August 6, 2026

#### Assignments
- **Repo-only assignments with no autograder** — An assignment can now be configured with no autograder at all. Every push to the default branch is collected as a submission for hand grading, and pushes to other branches are recorded in the commit history without becoming submissions ([#898](https://github.com/pawtograder/platform/pull/898))
- **Suggested due dates shown prominently** — When the **Suggested due dates** course flag is on, an assignment's advisory date is now surfaced clearly to students. Also fixed a timezone shift that could move dates by a day when creating an assignment ([#896](https://github.com/pawtograder/platform/pull/896))

### August 4, 2026

#### Command line
- **Pawtograder CLI published to npm** — The `pawtograder` command-line tool is now installable from npm, with the previously stubbed command groups implemented. See [CLI](/staff/cli) ([#885](https://github.com/pawtograder/platform/pull/885))

### August 3, 2026

#### Accessibility
- **Major accessibility work on student pages** — Student-facing pages were reworked for keyboard operation, focus handling, labelling, and contrast, measured against WCAG 2.1 AA, and an automated accessibility suite now runs against them on every change. This closed out the large structural barriers; a punchlist of smaller items remains open, so the student pages are not yet fully AA conformant ([#862](https://github.com/pawtograder/platform/pull/862))

#### Bug fixes
- **Preview as student on unreleased assignments** — The student preview on the **Test Assignment** page no longer closes itself when the assignment has not been released ([#887](https://github.com/pawtograder/platform/pull/887))
- **Renamed GitHub accounts re-linked** — Students and staff who rename their GitHub account are now re-matched automatically, and a course URL must be unique within its GitHub organization ([#888](https://github.com/pawtograder/platform/pull/888))

## July 2026

### July 17, 2026

#### Grading
- **Graded non-submitters flagged in the roster** — The grader roster now marks students who have been graded without ever submitting, so a stub submission created for grading is not mistaken for real work ([#865](https://github.com/pawtograder/platform/pull/865))

### July 16, 2026

#### Assignments
- **Unreleased assignments hidden from students** — Assignments that have not been released no longer appear on the student dashboard ([#866](https://github.com/pawtograder/platform/pull/866))

#### GitHub
- **Membership and repositories heal themselves** — GitHub organization membership and team assignment are reconciled the first time a student logs in, and a student repository that failed to be created is retried instead of needing staff intervention. Template repositories can also be set per deployment ([#866](https://github.com/pawtograder/platform/pull/866), [#861](https://github.com/pawtograder/platform/pull/861))

### July 6, 2026

#### Grading
- **Grade students without a submission** — Every enrolled student appears on the assignment roster. Students with no active submission show **Not submitted** and a **Grade anyway** button that creates an empty submission and opens it for grading; the progress panel counts them separately. **Bulk Assign Grading** gained an **Assign grading for all students** toggle that does the same in bulk. See [Grading assignments](/staff/assignments/grading-assignments#grade-anyway) ([#855](https://github.com/pawtograder/platform/pull/855))

#### Bug fixes
- **Non-submitter roster scoped per assignment** — Students who had submitted some other assignment in the course are no longer left off the non-submitter list for an assignment they skipped ([#859](https://github.com/pawtograder/platform/pull/859))
- **Grader names in bulk assign** — The assignee selector no longer shows blank entries while names are still loading ([#856](https://github.com/pawtograder/platform/pull/856))

## June 2026

#### Integrations
- **LMS (LTI) Sync** — Courses can connect to Canvas or another LTI 1.3 platform to pull the roster and push assignment grades back to the LMS gradebook. Site admins register platforms, and each course maps its LTI contexts to Pawtograder sections from **Course Settings → LMS (LTI) Sync** ([#789](https://github.com/pawtograder/platform/pull/789))

### June 23, 2026

#### Grading
- **Release checks that grading is finished** — Releasing grades now verifies that the reviews it covers are complete, and judges completeness according to each reviewer's role ([#844](https://github.com/pawtograder/platform/pull/844))

#### Administration
- **Class creation requires a GitHub organization** — The admin **Create Class** form now offers a required dropdown of configured GitHub organizations and accepts a list of instructor email addresses to invite. Admins can also run team synchronization for courses they do not teach ([#846](https://github.com/pawtograder/platform/pull/846), [#834](https://github.com/pawtograder/platform/pull/834))

### June 22, 2026

#### Groups
- **Group management tidied up** — Copying groups from another assignment is now done from the assignment's group management page, and students receive write access to their group's repository however they join the group, including by invitation and by staff assignment ([#839](https://github.com/pawtograder/platform/pull/839), [#850](https://github.com/pawtograder/platform/pull/850))

#### Branding
- **Per-deployment branding** — A Pawtograder deployment can set its own product name, logo, favicon, and accent color, so an institution running its own instance sees its own branding on the login and course pages ([#840](https://github.com/pawtograder/platform/pull/840))

### June 19, 2026

#### GitHub
- **GitHub organization defaults and an in-browser file editor** — Site admins can set default template repositories per GitHub organization from the **GitHub Orgs** dashboard, admins can enter a course as an instructor, and `pawtograder.yml` and workflow files can be edited in the browser with schema validation that blocks an invalid save ([#831](https://github.com/pawtograder/platform/pull/831))

### June 18, 2026

#### Assignments
- **Per-assignment repository configuration** — Assignment setup now covers how students get and hand in code in one place: a repository per student, a fork of the student's own repository from an earlier assignment, or no repository at all with students uploading their submission files directly. Assignments can also require a pull request, with settings for the upstream base branch, how the submission pull request is identified, and whether an open pull request is itself a graded condition. Pull-request assignments add **Checks** and **Deployments** tabs to the submission view, and instructors can create a submission on a student's behalf. See [Assignment configuration](/staff/assignments/configuration) ([#781](https://github.com/pawtograder/platform/pull/781))

### June 14, 2026

#### Assignments
- **Preview a test submission as a student** — On the **Test Assignment** page, **Preview as student** shows your own test submission under student rules, so you can check what students will see before releasing ([#835](https://github.com/pawtograder/platform/pull/835))

### June 8, 2026

#### Grades
- **Correct grades on the dashboard and in rollups** — The student dashboard shows the grade for the active submission, hand-grading totals roll up correctly, and a review score is never displayed below zero ([#824](https://github.com/pawtograder/platform/pull/824), [#812](https://github.com/pawtograder/platform/pull/812))

### June 5, 2026

#### Submissions
- **New submission file viewer** — The submission **Files** view now uses the same code editor as the rest of the platform in read-only mode, with syntax highlighting and steadier handling of large files and long grading sessions ([#565](https://github.com/pawtograder/platform/pull/565), [#820](https://github.com/pawtograder/platform/pull/820))

### June 4, 2026

#### Reporting
- **Assignment dashboard and rubric report** — Each assignment has a dashboard summarizing submissions, scores, and grading progress, and instructors can build a rubric report that shows how often each rubric check was applied, filtered by section, lab, or cohort. See [Assignment dashboard](/staff/assignments/assignment-dashboard) and [Rubric report](/staff/exports#rubric-report) ([#806](https://github.com/pawtograder/platform/pull/806))

#### Bug fixes
- **Lab sections can be deleted** — Deleting a lab section now removes it instead of leaving it in place ([#811](https://github.com/pawtograder/platform/pull/811))
- **No more error page without a course role** — Opening a course you have no role in sends you back to your course list instead of showing an error ([#830](https://github.com/pawtograder/platform/pull/830))

#### Grading

### May 19, 2026

#### Instructor tools

- **Faster instructor pages** — Large instructor tables stream in and render only the rows in view, so pages with thousands of rows stay responsive. #### Bug fixes
