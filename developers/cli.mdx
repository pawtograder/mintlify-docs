# Pawtograder CLI

The Pawtograder CLI provides command-line tools for instructors and site administrators to manage courses, copy assignments between semesters, import rubrics and submission data, and perform bulk repository operations.

## Installation

Install from npm:

```bash
npm install -g @pawtograder/cli
pawtograder --help
```

Or run without installing:

```bash
npx @pawtograder/cli --help
```

Requires Node.js 20 or later.

You can also run the CLI from a checkout of the platform repository:

```bash
npm run cli -- <command> [options]
```

To build and smoke-test the published bundle locally:

```bash
npm run cli:build
```

## Architecture

The CLI source lives at `cli/` in the repository root. It is shared by three consumers:

- `npm run cli` (via `cli/index.ts`) — loads `.env.local` / `.env` from the working directory
- Unit tests under `tests/unit/cli-*.test.ts`
- The published npm package (via `cli/bin.ts`) — does **not** read `.env` files

`packages/cli/` bundles `cli/bin.ts` with esbuild, which resolves the `@/cli/*` tsconfig path alias and inlines the CLI's own modules into a single file. The three runtime dependencies (`yargs`, `yaml`, `csv-parse`) stay external.

Every command POSTs `{ command, params }` to the `cli` Edge Function, which dispatches through the registry in `supabase/functions/cli/router.ts`.

## Authentication

Before using the CLI, authenticate with an API token.

### Creating an API token

1. Log in to the Pawtograder web app.
2. Navigate to **Settings → API Tokens**.
3. Create a new token with type **CLI** or **MCP + CLI**.
4. Copy the token. It starts with `mcp_`.

Scopes:
- `cli:read` — read-only operations (list, show, export)
- `cli:write` — write operations (copy, import, delete, assign)

### Logging in

```bash
pawtograder login
```

You'll be prompted to enter your API token. The token is stored in `~/.pawtograder/credentials.json` with mode `0600`.

You can also provide the token directly (for scripts and CI):

```bash
pawtograder login --token mcp_your_token_here
```

For self-hosted deployments, point `--url` at the **API gateway origin**, not the web host. The web host serves the application; the CLI talks to the `cli` Edge Function behind the API origin:

```bash
pawtograder login --url https://api.your-school.edu
```

Passing the web host produces an HTML response and the CLI will tell you so.

### Checking authentication

```bash
pawtograder whoami
```

### Logging out

```bash
pawtograder logout
```

## Commands

### Classes

List all classes your token can see:

```bash
pawtograder classes list
```

Show details for a specific class:

```bash
pawtograder classes show <class-id-or-slug>
```

### Assignments

List assignments for a class:

```bash
pawtograder assignments list --class <class-id-or-slug>
```

Show assignment details:

```bash
pawtograder assignments show <assignment-id-or-slug> --class <class-id-or-slug>
```

#### Copy assignments

Copy assignments between classes. Supports single-assignment copy, full-course copy, and schedule-driven copy:

```bash
# Copy a single assignment
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --assignment hw1 \
  --workdir /tmp/pawtograder-repos

# Copy all assignments
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --all \
  --workdir /tmp/pawtograder-repos

# Copy with a schedule CSV (custom due dates)
pawtograder assignments copy \
  --source-class cs3500-fall-2025 \
  --target-class cs3500-spring-2026 \
  --schedule schedule.csv \
  --workdir /tmp/pawtograder-repos
```

`--workdir` is required for repository content copying. The CLI uses local SSH git operations to avoid Supabase timeout limits.

**Options:**

| Option | Description |
|--------|-------------|
| `--source-class` | Source class (ID, slug, or name) |
| `--target-class` | Target class (ID, slug, or name) |
| `--assignment` | Single assignment to copy (ID or slug) |
| `--schedule` | CSV file with assignment slugs/titles and date overrides |
| `--all` | Copy all assignments from the source class |
| `--workdir` | Local directory for git clones (required unless `--skip-repos`) |
| `--dry-run` | Preview changes without making them |
| `--skip-repos` | Skip git repository operations |
| `--skip-rubrics` | Skip rubric copying |
| `--skip-surveys` | Skip copying surveys linked to assignments |
| `--concurrency` | Parallel clone/fetch operations (1–8, default 4) |
| `--delay-ms` | Delay between clone batches in milliseconds |

#### Schedule file format

```csv
slug,due_date
hw-01,2026-09-15T23:59:00
hw-02,2026-09-22T23:59:00
project-01,2026-10-01T23:59:00
```

#### Delete an assignment

```bash
pawtograder assignments delete <assignment-id-or-slug> --class <class-id-or-slug>
```

Add `--force` to skip the confirmation prompt.

### Submissions

List submissions with scores for an assignment:

```bash
pawtograder submissions list \
  --class cs3500-fall-2025 \
  --assignment hw1
```

Options:
- `--include-non-submitters` — also list enrolled students who have not submitted
- `--json` — emit raw JSON instead of a formatted table

#### Import or sync comments

Batch import submission comments from autograder results:

```bash
# Add-only import
pawtograder submissions comments import \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file batch-results.json \
  --author-profile-id <uuid>

# Sync (insert new + soft-delete missing)
pawtograder submissions comments sync \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file batch-results.json \
  --rubric-part-id <id>
```

Use `--rubric-part-id` instead of `--author-profile-id` to attribute comments to review assignment assignees.

#### Import artifacts

Upload submission artifact blobs from a manifest:

```bash
pawtograder submissions artifacts import \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --file manifest.json \
  --batch-size 5
```

**Options:**

- `--overwrite` — replace existing artifacts with the same name
- `--dry-run` — preview counts only
- `--batch-size <n>` — artifacts per API request (default 5)

The manifest is a JSON file with this structure:

```json
{
  "artifacts": [
    {
      "submission_id": 123,
      "name": "coverage-report",
      "data": {
        "format": "html",
        "display": "Coverage Report"
      },
      "content_base64": "PGh0bWw+Li4uPC9odG1sPg=="
    }
  ]
}
```

You can use `content_file` instead of `content_base64` to reference an external file.

### Reviews

List review assignments for an assignment:

```bash
pawtograder reviews list \
  --class cs3500-fall-2025 \
  --assignment hw1
```

Options:
- `--status pending|completed|all` — filter by completion state (default: all)
- `--rubric grading|self_review|meta|<id>` — restrict to one rubric
- `--assignee <name>` — filter by assignee name substring
- `--limit <n>` / `--offset <n>` — paginate results
- `--json` — emit raw JSON

#### Assigning grading work

`reviews assign` distributes submissions across active graders and instructors, balancing load round-robin. It honors `grading_conflicts` and never assigns someone their own submission.

```bash
# Preview a balanced split
pawtograder reviews assign \
  -c cs3500-fall-2026 \
  -a hw-1 \
  --due-date 2026-09-15 \
  --dry-run

# Create assignments
pawtograder reviews assign \
  -c cs3500-fall-2026 \
  -a hw-1 \
  --due-date 2026-09-15

# One assignment per rubric part
pawtograder reviews assign \
  -c cs3500-fall-2026 \
  -a hw-1 \
  --due-date 2026-09-15 \
  --by-part

# Restrict to specific graders
pawtograder reviews assign \
  -c cs3500-fall-2026 \
  -a hw-1 \
  --due-date 2026-09-15 \
  --grader <profile-id> \
  --grader <profile-id>
```

For allocations the round-robin cannot express, supply an explicit manifest:

```json
[{ "assignee_profile_id": "…", "submission_id": 123, "rubric_part_id": 45 }]
```

```bash
pawtograder reviews assign \
  -c cs3500-fall-2026 \
  -a hw-1 \
  --due-date 2026-09-15 \
  --file drafts.json
```

Re-running is safe: existing assignments are reused rather than duplicated.

A bare `--due-date` (for example, `2026-09-15`) means the **end of that day in the class's time zone**. Append a time (`2026-09-15T17:00`) for a specific time, or pass a timestamp with an offset to bypass the class zone.

### Help requests

```bash
# List all help requests
pawtograder help-requests list --class <identifier>

# Show only active (open or in-progress) requests
pawtograder help-requests list --class <identifier> --status active

# Filter by queue
pawtograder help-requests list --class <identifier> --queue "Office Hours"

# Close a help request
pawtograder help-requests close --id <id>

# Close with resolution details
pawtograder help-requests close \
  --id <id> \
  --status resolved \
  --resolution-status staff_helped \
  --notes "Helped with null pointer exception"
```

Status choices for `--status` on `list`: `open`, `in_progress`, `resolved`, `closed`, `active` (open or in_progress), `all`.

### Rubrics

List rubrics for an assignment:

```bash
pawtograder rubrics list \
  --assignment <assignment-id-or-slug> \
  --class <class-id-or-slug>
```

Export a rubric to YAML:

```bash
pawtograder rubrics export \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --type grading \
  --output hw1-rubric.yml
```

Use `--strip-ids` to omit database IDs, producing a template that creates new rows on import rather than updating existing ones.

Import a rubric from YAML:

```bash
# Preview changes (validates against the live rubric)
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading \
  --dry-run

# Apply changes
pawtograder rubrics import \
  --assignment hw1 \
  --class cs3500-spring-2026 \
  --file hw1-rubric.yml \
  --type grading
```

The `--dry-run` flag sends the YAML to the server for full validation and shows a plan of what would change (insertions, updates, deletions, point changes) without writing anything.

## Repository operations

Repository commands use local SSH git operations for reliability and performance.

<Warning>
Repository commands require SSH access to GitHub. Ensure your SSH keys are configured and you have access to the course organization.
</Warning>

### List repositories

```bash
pawtograder repos list --class <class-id-or-slug> --assignment <assignment-id-or-slug>
```

### Sync grade workflow

Synchronize `.github/workflows/grade.yml` from the handout repository to all student repositories:

```bash
pawtograder repos sync-grade-workflow \
  --class cs3500-spring-2026 \
  --assignment hw1 \
  --workdir /tmp/pawtograder-repos \
  --concurrency 2
```

**Options:**

- `--dry-run` — preview which repos would be updated
- `--concurrency <n>` — parallel git operations (1–8, default 2)
- `--delay-ms <n>` — delay between clone batches

### Cross-assignment copy

Copy files from source assignment repositories to target assignment repositories after the source due date:

```bash
pawtograder repos copy-after-source-due \
  --class cs3500-spring-2026 \
  --source-assignment hw1 \
  --target-assignment hw2 \
  --workdir /tmp/pawtograder-repos \
  --concurrency 2
```

**Options:**

- `--dry-run` — preview with `rsync -n` only
- `--mirror-delete` — pass `rsync --delete` (still excludes `.git`)
- `--concurrency <n>` — parallel operations (1–8, default 2)
- `--delay-ms <n>` — delay between batches

## JSON output

Every `list` command accepts `--json` to emit the raw API response instead of a formatted table. Progress output is suppressed so the stream is parseable:

```bash
# Find students without a score
pawtograder submissions list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.submissions[] | select(.student_total_score == null)'

# Count pending reviews
pawtograder reviews list -c cs3500-fall-2026 -a hw-1 --json \
  | jq '.summary.pending'
```

## Environment variables

| Variable | Description |
|----------|-------------|
| `PAWTOGRADER_HTTP_TIMEOUT_MS` | HTTP request timeout in milliseconds. Set to `600000` (10 minutes) for large operations. |
| `PAWTOGRADER_VERBOSE=1` | Log each request and its timing to stderr. |
| `DEBUG=1` | Enable verbose HTTP logging plus stack traces on unexpected errors. |

The CLI does not read `.env` files when installed from npm. The in-repo `npm run cli` entry point does load `.env.local` / `.env`.

## API token scopes

CLI tokens require specific scopes:

- `cli:read` — read-only operations (list, show, export)
- `cli:write` — write operations (copy, import, delete, assign)

Create tokens with appropriate scopes in the web UI under **Settings → API Tokens**.

## Best practices

1. **Use dry-run first.** Preview changes with `--dry-run` before executing.
2. **Export backups.** Export rubrics before importing new versions.
3. **Batch size.** For artifact imports, reduce `--batch-size` if requests time out.
4. **Dedicated workdir.** Use a dedicated directory for `--workdir` to avoid conflicts.
5. **Concurrency.** Start with the default and adjust based on network performance.

## Troubleshooting

### Authentication errors

If you see "Not logged in" or "Authentication failed":

1. Run `pawtograder login` to re-authenticate.
2. Verify your token is valid in the web UI (**Settings → API Tokens**).
3. Ensure your token has the correct scopes (`cli:read` or `cli:write`).
4. For self-hosted deployments, confirm `--url` points to the API gateway origin (for example, `https://api.your-school.edu`), not the web host.

Common HTTP errors:

- **401 Unauthorized** — token expired or revoked. Log in again.
- **403 Forbidden** — token lacks required scopes.
- **504 Gateway Timeout** — operation took too long. Increase the timeout or use smaller batches.

### Timeout errors

For large operations (copying many assignments, importing large artifacts):

1. Set a longer timeout: `PAWTOGRADER_HTTP_TIMEOUT_MS=600000 pawtograder ...`
2. Use smaller batch sizes (for example, `--batch-size 1` for artifact imports).
3. Use `--dry-run` first to validate before running the full operation.

### Repository clone failures

If SSH git operations fail:

1. Verify SSH keys are configured: `ssh -T git@github.com`
2. Check that you're a member of the course's GitHub organization.
3. Retry with lower `--concurrency` (try 2 or 1).
4. Use `--delay-ms 1000` to add delays between batches.
