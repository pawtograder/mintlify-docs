# Deployment skinning

Self-hosted deployments can re-brand the app — service name, tagline, logos, favicon, accent color, and sign-in SSO buttons — **without rebuilding the web image**. Branding is delivered as plain (non-`NEXT_PUBLIC_*`) runtime environment variables read server-side on every request (`lib/branding.ts`) and handed to the client via React context, so the same published `ghcr.io/pawtograder/web` image renders whatever branding the Helm chart injects.

## Helm chart configuration

Configure branding under `web.branding` in your values overlay:

```yaml
web:
  branding:
    name: "MyGrader"                    # page titles, headings, wordmarks
    description: "…"                    # <meta name="description">
    tagline: "…"                        # line under the wordmark on auth screens
    logoLight: "/Logo-Light.png"        # bundled path OR absolute https:// URL
    logoDark: "/Logo-Dark.png"          # bundled path OR absolute https:// URL
    favicon: "/favicon.svg"             # browser-tab icon; bundled path OR https:// URL
    colorPalette: "teal"                # accent: gray|red|orange|yellow|green|teal|blue|cyan|purple|pink
```

Any field left blank keeps its built-in Pawtograder default.

## Logos and favicon

Custom logos and the favicon can be provided two ways:

**Absolute `https://` URL** — logos render with a plain `<img>` (no `next.config` image-host allow-listing needed), and the favicon is set via `<link rel="icon">`.

**Baked into the image (recommended)** — drop your files into `public/branding/` before `docker build`. Everything under `public/` is copied into the web image and served at `/branding/*`. Then point the values at those paths:

```yaml
web:
  branding:
    name: "TartanGrader"
    logoLight: "/branding/logo-light.png"
    logoDark: "/branding/logo-dark.png"
    favicon: "/branding/favicon.png"
    colorPalette: "red"
```

The same published image still re-skins per deployment from the env vars; the assets just need to be present inside it. A worked example (CMU-themed **TartanGrader**) lives in `charts/pawtograder/examples/values-tartangrader.yaml`.

## Single sign-on (SSO)

The sign-in page renders one button per provider in `web.branding.ssoProviders` (in order). Leaving it empty keeps the historical default — a single **Continue with Microsoft (Northeastern Login)** button. Configuring SSO is a two-part job: the **button** (frontend) and the **provider** (GoTrue) must both be set up.

### 1. Buttons (frontend)

```yaml
web:
  branding:
    ssoProviders:
      - provider: google          # Supabase/GoTrue OAuth provider id
        label: "Continue with Google"
        icon: google              # microsoft|github|google|apple|discord|gitlab|slack|twitch|linkedin|sso|generic
      - provider: azure
        label: "Continue with Microsoft"
        icon: microsoft
        scopes: "email User.Read" # optional OAuth scopes
```

Allowed `provider` values: `apple, azure, bitbucket, discord, facebook, figma, github, gitlab, google, kakao, keycloak, linkedin_oidc, notion, slack_oidc, spotify, twitch, workos, zoom`.

To show **no** SSO buttons (email-only), set `BRAND_SSO_PROVIDERS: "[]"` via `web.extraEnv`.

### 2. Provider (GoTrue)

Enable each provider and supply its OAuth client id/secret. `github`, `azure`, and `discord` have first-class blocks; everything else uses the generic `auth.externalProviders` list:

```yaml
auth:
  external:
    github: { enabled: true }   # reads GITHUB_OAUTH_CLIENT_ID / _SECRET
    azure: { enabled: true }    # reads AZURE_OAUTH_CLIENT_ID / _SECRET
  externalProviders:
    - name: google              # -> GOTRUE_EXTERNAL_GOOGLE_*
      enabled: true             # reads GOOGLE_OAUTH_CLIENT_ID / _SECRET from the web Secret
    - name: keycloak
      enabled: true
      url: https://sso.example.edu/realms/main  # some providers require an issuer URL
```

Each enabled provider's redirect URI defaults to the API gateway origin + `/auth/v1/callback`. Register that exact URL in the provider's OAuth app. Put the client id/secret in the `pawtograder-web` Secret under the `<NAME>_OAUTH_CLIENT_ID` / `<NAME>_OAUTH_CLIENT_SECRET` keys (e.g. `GOOGLE_OAUTH_CLIENT_ID`).

The redirect URI depends on `global.apiOnSeparateHost`:

- **Separate API host (default):** `https://api.<hostname>/auth/v1/callback`
- **Path-based routing (`apiOnSeparateHost: false`):** `https://<hostname>/auth/v1/callback`

## Environment variables reference

The following environment variables are read by `lib/branding.ts` at request time. They are injected by the Helm chart from `web.branding.*` values; you can also set them directly via `web.extraEnv`.

| Variable | Default | Description |
|---|---|---|
| `BRAND_NAME` | `Pawtograder` | Product name in titles, headings, and wordmarks. |
| `BRAND_DESCRIPTION` | `Pawtograder is an application for managing student assignments` | `<meta name="description">`. |
| `BRAND_TAGLINE` | `Your pawsome course companion` | Short line under the wordmark on auth screens. |
| `BRAND_LOGO_LIGHT` | `/Logo-Light.png` | Logo for light mode. Bundled path or absolute URL. |
| `BRAND_LOGO_DARK` | `/Logo-Dark.png` | Logo for dark mode. Bundled path or absolute URL. |
| `BRAND_FAVICON` | `/favicon.ico` | Browser-tab icon. Bundled path or absolute URL. |
| `BRAND_COLOR_PALETTE` | `gray` | Chakra accent palette. |
| `BRAND_SSO_PROVIDERS` | Microsoft/Azure button | JSON array of `{provider, label, icon?, scopes?}`. |
