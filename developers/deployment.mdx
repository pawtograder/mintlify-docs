# Kubernetes Deployment (Helm)

Pawtograder ships a Helm chart that bundles the Next.js web app together with all Supabase services it depends on (Postgres, GoTrue, PostgREST, Realtime, Storage API, Edge Functions, Kong, Studio, postgres-meta, and Supavisor) so the entire stack can be deployed from a single Helm release.

## Components

| Component | Image | Default replicas |
|---|---|---|
| postgres | `supabase/postgres:17` | 1 (StatefulSet) |
| supavisor | `supabase/supavisor` | 2 |
| gotrue (auth) | `supabase/gotrue` | 2 |
| postgrest | `postgrest/postgrest` | 2 |
| realtime | `supabase/realtime` (clustered) | 3 (StatefulSet) |
| storage-api | `supabase/storage-api` | 2 |
| imgproxy | `darthsim/imgproxy` | 1 |
| postgres-meta | `supabase/postgres-meta` | 1 |
| studio | `supabase/studio` | 1 |
| edge-runtime | `ghcr.io/pawtograder/edge-functions` | 2 |
| kong | `kong:3` | 2 |
| web (Next.js) | `ghcr.io/pawtograder/web` | 2 |

## Prerequisites

- Kubernetes ≥ 1.27
- Helm ≥ 3.14
- An ingress controller (e.g. nginx) with cert-manager for TLS
- An S3-compatible object store for file storage
- (Optional) OpenBao + External Secrets Operator for production secret management

## Quick start

The chart requires ~15 secret values in the `pawtograder-jwt` Secret. Use the helper script to generate them:

```bash
# 1. Generate the full JWT bundle
npx tsx scripts/GenerateJwtKeys.ts --env > .secrets/pawtograder-jwt.env

# 2. Create Kubernetes secrets
kubectl create namespace pawtograder
kubectl -n pawtograder create secret generic pawtograder-jwt \
  --from-env-file=.secrets/pawtograder-jwt.env
kubectl -n pawtograder create secret generic pawtograder-postgres \
  --from-literal=POSTGRES_PASSWORD=$(openssl rand -base64 32) \
  --from-literal=PAWTOGRADER_PASSWORD=$(openssl rand -base64 32)
kubectl -n pawtograder create secret generic pawtograder-s3 \
  --from-literal=AWS_ACCESS_KEY_ID=$S3_KEY \
  --from-literal=AWS_SECRET_ACCESS_KEY=$S3_SECRET

# 3. Install the chart
helm install pawtograder oci://ghcr.io/pawtograder/charts/pawtograder \
  --version 0.1.0 \
  --namespace pawtograder \
  --set global.hostname=pawtograder.example.com \
  --set ingress.className=nginx \
  --set postgres.persistence.storageClass=local-path \
  --set storage.backend=s3 \
  --set storage.s3.endpoint=https://s3.example.com \
  --set storage.s3.bucket=pawtograder
```

## Required secrets

When `secrets.create=false` (the default), you must pre-provision these Kubernetes Secrets:

| Secret name | Required keys |
|---|---|
| `pawtograder-postgres` | `POSTGRES_PASSWORD`, `PAWTOGRADER_PASSWORD` |
| `pawtograder-jwt` | `JWT_SECRET`, `ANON_KEY`, `SERVICE_ROLE_KEY`, `JWT_PRIVATE_JWKS`, `JWT_PUBLIC_JWKS`, `JWT_REALTIME_JWKS`, `REALTIME_ENC_KEY`, `PG_META_CRYPTO_KEY`, `PGSODIUM_ROOT_KEY` |
| `pawtograder-smtp` | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_ADMIN_EMAIL` (if SMTP enabled) |
| `pawtograder-s3` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (if S3 storage) |
| `pawtograder-web` | Optional. Mounted into the web pod for GitHub App, Discord, Canvas, LLM credentials. |
| `pawtograder-edge-functions` | Optional. Mounted into the edge-runtime pod. |

Use `scripts/GenerateJwtKeys.ts` to generate the full JWT bundle.

<Warning>
`JWT_SECRET` must be at least 64 characters. Shorter values cause Realtime to crash-loop with "secret_key_base is too short."
</Warning>

## Per-PR preview environments

The chart includes a GitHub Actions workflow (`.github/workflows/preview.yml`) that automatically deploys a full Pawtograder stack for every pull request and tears it down when the PR closes.

Each preview gets:
- Its own Kubernetes namespace (`pawtograder-preview-pr-<number>`)
- Fresh JWT keys and database passwords
- A seeded demo class with sample instructor, grader, and student accounts
- A public URL at `pr-<number>.preview.pawtograder.net`

The preview workflow builds four Docker images per PR:
- `web` — Next.js frontend (baked with preview-specific `NEXT_PUBLIC_*` values)
- `edge-functions` — Deno edge runtime with pre-compiled `.eszip` bundles
- `migrations` — Postgres migration runner
- `seeder` — Demo class seeder

## Build-time vs runtime environment variables

`NEXT_PUBLIC_*` variables are inlined into the client bundle at build time. The chart cannot override them at runtime. Build the web image with the correct hostname and anon key for your deployment:

```bash
docker build \
  --build-arg NEXT_PUBLIC_PAWTOGRADER_WEB_URL=https://staging.pawtograder.net \
  --build-arg NEXT_PUBLIC_SUPABASE_URL=https://api.staging.pawtograder.net \
  --build-arg NEXT_PUBLIC_SUPABASE_ANON_KEY=$ANON_JWT \
  -t ghcr.io/pawtograder/web:$VERSION .
```

The release pipeline (`release-images.yml`) reads the anon key directly from the cluster's `pawtograder-jwt` Secret at build time so the baked value always matches the running JWT bundle.

## Monitoring

Enable Prometheus metrics and Grafana dashboards by setting `monitoring.enabled=true`. The chart emits ServiceMonitor CRs and Grafana-discoverable ConfigMaps — it does **not** deploy Prometheus or Grafana itself.

Five dashboards are included:

| Dashboard | Covers |
|---|---|
| Stack Overview | Pod readiness, restart count, error rate, p95 latency |
| Postgres Deep Dive | Cache hit, replication lag, top statements, table sizes |
| Realtime Fanout | Connection churn, broadcast rate, Erlang VM load |
| Edge Functions | Per-function RPS, p95 latency, errors |
| App Business | Submissions/min, grading actions, queue depth, per-class views |

When monitoring is enabled, three additional keys are required in `pawtograder-jwt`:

| Key | Purpose |
|---|---|
| `REALTIME_METRICS_BEARER` | Scrapes `realtime:/metrics` |
| `SUPAVISOR_METRICS_BEARER` | Scrapes `supavisor:/metrics` |
| `METRICS_SCRAPE_TOKEN` | Scrapes `web:/api/metrics` |

## Shared Redis cache

With multiple web replicas, Next.js's default in-memory cache means `revalidateTag()` only invalidates the replica that handled the request. The chart supports a shared Redis-backed cache handler (`cache-handler.cjs`) that makes tag invalidation global across all replicas.

Set `redis.provider=shared` and point at a cluster-shared Redis instance. Bootstrap manifests for the shared Redis are in `charts/pawtograder/examples/shared-redis/`.

## Values reference

Common configuration knobs:

```yaml
global:
  hostname: pawtograder.example.com
  apiOnSeparateHost: true   # api.<hostname> vs path-based
  nodeSelector: {}
  tolerations: []

ingress:
  enabled: true
  className: ""
  tls:
    enabled: true
    secretName: pawtograder-tls

postgres:
  persistence:
    storageClass: ""
    size: 50Gi

realtime:
  replicas: 3
  spreadAcrossNodes: true   # podAntiAffinity hint

monitoring:
  enabled: false
```

See `charts/pawtograder/values.yaml` in the repository for the full reference.
